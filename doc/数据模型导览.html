01 · 先懂这几个词

概念速查

看表之前，先认识几个会反复出现的小概念。它们就像数据世界的"基本零件"。

主键 id
每条记录的唯一编号，系统自动往下排，不会重复。
类比就像每本书在图书馆的索书号，凭它就能精准找到这一本。
外键 _id
一个"指针"，指向另一张表里的某条记录，表示"我属于它"。
类比像书的封面上写着"分类：工作能力提升"——这个分类名本身记在另一本花名册里。
软删除 deleted_at
不是真删，而是盖一个"已扔进回收站"的时间戳，还能捞回来。
类比把书放进纸箱而不是烧掉，哪天反悔还能从箱子里取回。
JSON 列
一个"口袋"字段，里面可以塞任意结构的小内容，不用每次加需求就改表。
类比像书后夹的便签本，想记什么就写什么，不规定格式。
唯一约束 UNIQUE
规定某个组合不能重复，防止你建出两个一模一样的分类或标签。
类比图书馆不会登记两本索书号相同的书。
级联删除 CASCADE
那边删了，这边引用它的记录自动跟着消失，避免留下"指向空气"的断链。
类比一本书被彻底销毁，夹在里面的书签自然也一并没了。
枚举 ENUM
这个字段只能填预先列好的几个值之一，不能乱填。
类比状态只能从"在读/已读/…"里选，不能自己造一个"半读"。
owner_id
"这份数据归谁所有"。目前只有你一个人，但为以后多人共用埋好伏笔。
类比每本书盖个藏书章，写明是谁的；现在章都一样，将来好分。
02 · 为什么这么设计

关键决策

这几条是整个数据模型的"骨架选择"，决定了后续功能好不好长出来。每条都对应你之前拍板的产品方向。

1

一本书只有一个分类

分类是"这本书对我个人的主要用途"（如工作能力提升、文学作品、语言学习），一本书只有一种核心立场。所以用单个指针 category_id，不做多对多关联表。

2

"存"是独立状态，绝不等于删除

状态枚举里有 STORED（存），表示"保留但退出当前优先级"；而删除走的是 deleted_at 回收站路径。两条路完全分开，不混用——这是你定的红线。

3

阅读痕迹归原书，主题只"引用"

高亮、笔记直接属于原书；主题只是把它们"框过来看"，不占有原件。主题删除走软删除，只隐藏主题和引用；原件被物理删除时，主题侧引用自动消失。

4

AI 生成内容单独存放

AI 产出的摘要、问答等放在独立的 ai_assets 表，和你的手写笔记物理分开，绝不分混。导出时也分目录，确保 AI 不"绑架"你的原始资产。

5

笔记同时存 HTML 和 Markdown 两份

编辑用 HTML（富文本编辑器需要），导出用 Markdown（通用可读）。双存避免来回转换出错，笔记一改就同步重写两份。

6

根实体带 owner_id，为多人留口子

书籍、分类、标签、笔记、主题等用户拥有的根实体盖"归属章"；关联表和历史表通过父表继承归属。将来要开到 ≤5 人，重点是补登录和查询边界。

04 · 一张一张看

逐表讲解

每张表列出字段、类型，以及"这字段到底是干啥的"。带 ★ 的是核心枢纽表。阶段标签说明它首次出现在哪一步。

Step 1 · 地基层（框架 + 书籍管理）

users

S1 — 谁在用这个系统
id主键
INTEGER
这个用户的系统编号。
username*
TEXT
登录用的名字，不能重复。
password_hash*
TEXT
密码的"加密指纹"。不存明文密码，只存算出来的哈希，登录时比对。
display_name
TEXT
界面上显示的名字，可空。
created_at / updated_at
TEXT
创建和最近修改时间。

目前只有你一个人，初始化时写一条记录即可。

books

S1 — ★ 一本书的完整档案
id主键
INTEGER
这本书的系统编号。
owner_id外键
INTEGER
归谁所有（现在恒为你）。为多人预留
category_id外键
INTEGER
属于哪个分类。一本书只能有一个，对应"这本书对我的主要用途"。
title*
TEXT
书名。必填。
author*
TEXT
作者。必填。其余元数据都可选。
isbn / publisher / publish_year
TEXT/INT
ISBN、出版社、出版年，都可留空后补。
description / language
TEXT
简介、语言。
cover_path
TEXT
封面图缓存路径。上传 EPUB 时自动抽取。
status*
ENUM
阅读状态：收录/计划读/在读/已读/存。"存"≠删除，见决策2
visibility*
ENUM
公开 / 私有。默认私有。
reading_purpose
TEXT
阅读目的（精读/泛读/参考…），自由填。表达方式暂未锁定
rating
INTEGER
1–5 星评分，可空。
custom_attributes
JSON
"口袋字段"，想加什么自定义属性就塞这里，不用改表。弹性扩展
metadata_source
TEXT
元数据怎么来的：手填 / NeoDB / 豆瓣。
deleted_at
TEXT
软删除标记。空=在册，有值=在回收站。与"存"状态无关
created_at / updated_at
TEXT
创建与最近修改时间。

book_files

S1 — 一本书挂了哪些文件
book_id外键
INTEGER
属于哪本书。
file_path*
TEXT
文件在磁盘上的位置。文件本体存盘，表里只记路径。
file_format*
TEXT
格式：EPUB/PDF/MOBI…。只有 EPUB 能在线读，其他只存档下载。
is_primary*
INTEGER
是不是主阅读文件。一本书至多标一个。
file_size / checksum
INT/TEXT
文件大小、校验值（用来查重复/完整性）。

categories

S1 — 你自定义的分类
owner_id外键
INTEGER
分类归谁。分类因人而异，不内置通用类型树。
name*
TEXT
分类名，如"工作能力提升"。同一人下不能重名。
parent_id外键
INTEGER
可选的上级分类，目前平级使用，结构上留好层级不强制。

tags + book_tags

S1 — 标签（多对多）
tags.name*
TEXT
标签名，如"方法论"。标签可以多个贴一本书，和分类不同。
book_tags
关联表
"哪本书贴了哪个标签"的对照表。多对多的桥梁

book_relations

S1 — 书与书的关联
source / target
INTEGER
两本书的编号。你主动建立的关系（如续集、同主题、对照）。
relation_type
TEXT
关系类型，自由描述。

status_history

S1 — 这本书的状态流转史
from → to
TEXT
从什么状态变成什么状态。每次改状态自动记一条，形成时间轴。
changed_at
TEXT
变更时间。

settings

S1 — 应用配置
key + value
TEXT/JSON
配置项，如回收站保留天数、主题、AI 配置、OSS 配置。S1 先能存配置，功能后置。
Step 2 · 阅读器与笔记沉淀

reading_progress

S2 — 读到哪了
cfi*
TEXT
epub.js 的"书内坐标"，精确到段落。关书存、开书回。
percentage
REAL
进度百分比，给界面显示用。
last_read_at
TEXT
最近一次阅读时间。最近阅读列表靠它排。

highlights

S2 — 高亮与划线
cfi_start / cfi_end*
TEXT
选中文字的起止坐标，重开书时按它把高亮画回去。
text*
TEXT
选中的原文。CFI 万一漂移，靠原文兜底重新定位。技术风险对策
type*
ENUM
高亮 / 划线 两种。
note
TEXT
高亮上挂的附注批注。
mark_type
ENUM
标记：重要/疑问/启发，可扩展。预留更多标记类型

notes

S2 — 独立笔记
cfi
TEXT
关联位置，可空（无位置的纯笔记）。
content_html
TEXT
富文本内容，编辑器用它。
content_markdown
TEXT
Markdown 副本，导出用。和 HTML 双存。见决策5
deleted_at
TEXT
软删除，可恢复。
Step 3 · AI 派生资产（隔离存放）

ai_assets

S3+ — AI 生成的内容
scope_type*
ENUM
作用域：某本书 / 某主题 / 全局。
kind*
ENUM
类型：摘要/问题清单/标签建议/比较…
content*
TEXT
AI 生成的内容本身。
references
JSON
引用依据：来自哪本书哪章哪条高亮。让 AI 回答可追溯，不是黑箱。见决策4
provider / model
TEXT
哪个 AI、哪个模型生成的，留痕。

这张表和你手写的 notes/highlights 物理分开，展示和导出都分开设。

Phase 2 · 主题阅读（引用，不占有）

topics + topic_*

P2 — 主题及其引用
topics
主表
主题对象本身：名称 + 说明。是独立对象，不是标签。
topic_books
关联表
主题关联了哪些书（多对多）。
topic_highlights / notes
引用表
主题"框"了哪些高亮/笔记来看。主题软删除不清引用；原件物理删除时引用自动消失。见决策3
topic_segments
引用表
主题引用的章节片段，复用阅读器的 CFI 机制。
topic_entries
主表
主题自己的沉淀：待探索问题 / 阶段判断 / 比较结论。
