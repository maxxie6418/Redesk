## 文档说明

- 本文档规定"数据怎么存"。表结构按阶段完成概念设计，按开发阶段迁移落地；近期实现只创建当前阶段所需表，后续阶段按本文继续补迁移，避免临场重新建模。
- 版本号遵循三段式「主.次.修订」，递增规则见《决策记录》版本号规范。
- 阶段标注：`S1`=Step1 地基层 / `S2`=Step2 阅读器 / `S3`=Step3 AI 阶段一 / `P2`=Phase2 主题阅读。标注仅说明首次引入阶段，表结构当前即按完整形态设计。
- 字段类型以 SQLite 实际存储类型表述（INTEGER / TEXT / REAL / BLOB / JSON）；JSON 列在 SQLite 中以 TEXT 存储，应用层解析。
- 主键统一为 `id INTEGER PRIMARY KEY`（自增 rowid 别名）；时间戳统一 `TEXT`（ISO 8601 UTC）。
- 用户拥有的根实体表带 `owner_id`（关联 users），当前单账户下恒为同一值；从属关系表、历史表、引用表通过父表继承归属，查询与写入必须校验 owner 边界，预留 ≤5 人轻量隔离。

## 1. 建模决策

| 决策 | 结论 | 依据 |
| --- | --- | --- |
| 一书一分类 | `books.category_id` 单意外键，不建多对多关联表 | 分类是"这本书对个人的主要用途/立场"（如工作能力提升、文学作品、语言学习），一书只有一种核心定位 |
| 分类用户自定义 | `categories` 表属用户所有，当前平级使用，结构留可选 `parent_id` 层级不强制 | 个人用途分类因人而异，不内置通用类型树 |
| `存档` 独立状态 | 状态枚举含 `STORED`，与软删除 `deleted_at` 完全不同路径 | 决策记录：`存档`为正式业务状态，不得实现为删除/归档 |
| 软删除统一字段 | 用户可删数据用 `deleted_at TEXT NULL` 标记，非物理删除 | 回收站恢复需求（1.25） |
| 阅读痕迹归属原书 | 高亮/笔记 `book_id` 直接归属原书；主题仅"引用" | 决策记录：主题不拥有原始阅读痕迹 |
| 主题软删除与软引用 | `topics.deleted_at` 表示主题软删除；主题引用表不拥有原始痕迹。原痕物理删除时引用自动摘除；主题软删除时仅隐藏主题及其引用，不动原始数据 | 决策记录：主题是重组再利用层 |
| AI 派生资产隔离 | `ai_assets` 独立表，不与用户笔记/高亮混表 | 决策记录：AI 生成内容必须与用户原始内容区分 |
| 弹性字段 | `books.custom_attributes` JSON 列承载自定义收藏属性 | 避免频繁改表（1.12） |
| owner_id 预留 | 根实体直接带 `owner_id`；从属表通过父表继承 owner，不强制冗余；无父实体的暂存资源需自带 `owner_id` | 决策记录：保留向多用户演进空间 |
| 进度独立表 | `reading_progress` 独立于 books，按 (book_id, owner_id) | 进度属阅读行为，与书籍元数据解耦；便于多文件/多用户扩展 |
| 笔记双格式存储 | `notes.content_html` + `content_markdown` 双存 | 编辑用 HTML（TipTap），导出用 Markdown，避免反复转换 |

## 2. ER 关系总览

```
users (S1)
  │ owner_id 贯穿用户根实体；从属表经父表继承
  ▼
books ──< book_files                 (一书多文件, S1)
  │── category_id ── categories      (一书一分类, S1)
  │──< book_tags ── tags             (多对多标签, S1)
  │──< book_relations ── books       (书-书关联, 自引用, S1)
  │──< status_history                (状态时间轴, S1)
  │──< reading_progress              (1:1 进度, S2)
  │──< highlights                    (高亮/划线, S2)
  │──< notes                         (独立笔记, S2)

topics ──< topic_books ── books      (多对多, P2)
  │──< topic_highlights ── highlights (软引用, P2)
  │──< topic_notes ── notes          (软引用, P2)
  │──< topic_segments                (章节片段引用, P2)
  │──< topic_entries                 (问题/判断/比较, P2)

ai_assets                            (AI 派生资产, S3+)
  │ scope → book / topic / global

settings                             (应用配置, S1)
```

### 3.3 book_files（书籍文件） `S1`

| 字段 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| id | INTEGER | PK AUTO | |
| owner_id | INTEGER | NOT NULL FK users | 归属用户；未关联文件池按此隔离 |

| local_path | TEXT | | 本地相对路径（主端为本地时必填） |
| remote_key | TEXT | | 云端对象 key（主端为云端时必填） |
| primary_location | TEXT | NOT NULL DEFAULT 'local' | 主端位置：`local` / `cloud` |
| sync_status | TEXT | NOT NULL DEFAULT 'synced' | 双端同步状态：`synced` / `pending` / `partial_failed` / `failed` |
| original_filename | TEXT | | 原始文件名 |
| file_format | TEXT | NOT NULL | EPUB/PDF/MOBI/TXT/AZW3… |
| mime_type | TEXT | | |
| file_size | INTEGER | | 字节 |
| checksum | TEXT | | SHA-256 校验值（去重/完整性） |
| is_primary | INTEGER | NOT NULL DEFAULT 0 | 主阅读文件标记 |
| created_at | TEXT | NOT NULL | |
| updated_at | TEXT | NOT NULL | |

约束：同一 book 下至多一条 `is_primary=1`（应用层保证）；`book_id` 为 null 时表示文件暂存于未关联文件池，可通过匹配操作关联到书籍；同一 `owner_id` 下按 `checksum` 检测重复文件。`dual` 模式下主端由 `primary_location` 决定，另一端标记为 `pending`，由后续同步任务补齐。

## 6. 全文检索（FTS5）

使用 SQLite FTS5 外部内容表，通过触发器与源表同步。

- **books_fts**（`S1`）：分词字段 title、author、isbn。支撑书籍搜索（1.13）。
- **notes_fts**（`S2`）：分词字段 content_markdown。支撑笔记全文搜索（3.20）。
- **highlights_fts**（`S2`）：分词字段 text。支撑高亮内容检索。

> 整本书正文检索（3.25，单本书内）属增强/待定位，本期不建对应 FTS；若后续纳入，按单书导入时抽取正文建索引，查询仍为毫秒级，详见《技术方案》§4.1 检索分层。

---

## 7. 向量检索（sqlite-vec）

`S3` / `P2` 引入，复用同一 SQLite 文件。

- **embeddings**（vec0 虚拟表）：`rowid` 映射到源对象，字段 `source_type`（HIGHLIGHT/NOTE/SEGMENT）、`source_id`、`embedding float[N]`（维度随 embedding 模型，如 768/1536）。
- 用途：AI 阶段二 RAG 语义检索（9.13）、主题关联发现。
- 嵌入由外部 embedding API 生成，用户自带 key；写入时同步建向量，删除源对象时删除对应向量。

## 9. 演进与待定

- **多用户**：根实体 `owner_id` 已就位；未来开 ≤5 人时，从属表通过父表校验 owner，通常仅需加注册/登录与查询约束，不改主体结构。
- **权限分级**：§7 细粒度权限为预留；当前仅 `visibility` 字段，未来可加权限规则表，不动现有结构。
- **多书库**：预留方向；若引入，以新增 `library_id` 挂载，不影响当前单书库模型。
- **主题字段最小集**：决策记录暂缓；当前 topics 仅 name+description，其余需求走弹性字段或后续补列。
- **阅读目的表达方式**：决策记录暂缓；当前 `books.reading_purpose` 自由文本，未锁定书籍级/任务级。
- **AI 分级访问**：决策记录暂缓；当前 ai_assets 无保密分级字段，阶段三接入检索层时补 `access_level` 策略。

> 本文档为 Redesk 数据模型 v1.0.2，待评审。评审通过后作为 API 接口设计与 Drizzle schema 实现的直接依据。
