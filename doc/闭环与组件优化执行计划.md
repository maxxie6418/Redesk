# 闭环与组件优化执行计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 按模块补齐当前已发现的闭环缺口，并逐步降低前后端巨型文件、重复组件与数据契约漂移带来的维护风险。

**Architecture:** 本计划先处理数据安全与一致性，再处理功能闭环缺口，最后做结构性拆分与组件复用。所有修改保持现有技术栈不变：Fastify + Drizzle + SQLite + React + TanStack Query + shadcn/ui。

**Tech Stack:** TypeScript、Fastify、Drizzle ORM、SQLite/FTS5、React 18、Vite、TanStack Query、Vitest、ESLint。

---

## 执行原则

- 修改前已有基线提交：`chore(review): 建立优化执行前基线`。
- 每轮优先保持可验证、可回退，避免一次性重构多个独立模块。
- P0/P1 以修复闭环与数据一致性为主；P2/P3 再做结构拆分。
- 涉及数据库 schema 的变更必须同步迁移、共享 schema、API 行为与测试。
- 完成代码修改后必须运行：
  - `pnpm typecheck`
  - `pnpm lint`
- 涉及后端逻辑时优先补对应 Vitest 用例。
- 不改变已确认技术栈，不引入新依赖，除非单独确认。

## 阶段 1：P0 数据安全与一致性修复

### Task 1: 修复系统重置表清理范围

**Files:**
- Modify: `apps/api/src/routes/system.ts`
- Test: `apps/api/src/routes/system.test.ts`

**Rationale:** 当前系统重置只清理 M1 表，遗漏 `notes`、`highlights`、`topics`、`topic_*`、`reading_progress`、`notes_fts`、`highlights_fts` 等已上线表，可能导致重置后残留阅读痕迹和主题数据。

- [ ] Step 1: 在 `system.test.ts` 增加失败用例，插入书籍、阅读进度、高亮、笔记、书签、主题及主题关联后调用系统重置。
- [ ] Step 2: 运行 `pnpm --filter @redesk/api test -- system.test.ts`，确认新增用例失败且失败原因为数据残留。
- [ ] Step 3: 更新 `system.ts` 的 reset 表列表，按依赖顺序清理：主题引用/条目/片段、阅读痕迹、文件/封面/关系、书籍、配置、用户、FTS 表。
- [ ] Step 4: 运行同一测试，确认通过。

### Task 2: 阅读进度写入校验 book/file 归属

**Files:**
- Modify: `apps/api/src/routes/reading-progress.ts`
- Test: `apps/api/src/routes/notes.test.ts` 或新增对应阅读进度测试文件

**Rationale:** 当前 `PUT /books/:id/reading-progress` 直接写入 `file_id`，未校验文件是否属于当前用户和当前书籍，可能造成跨书或跨 owner 的脏数据。

- [ ] Step 1: 增加失败用例：使用不属于该书的 `file_id` 写入阅读进度，应返回 404 或业务错误。
- [ ] Step 2: 增加失败用例：使用不存在的 `book_id` 或非当前 owner 的书籍，应返回 404。
- [ ] Step 3: 在 `reading-progress.ts` 写入前查询 `books` 与 `book_files`，同时校验 `owner_id` 与 `book_id`。
- [ ] Step 4: 运行阅读进度相关测试，确认通过。

### Task 3: 全量备份权限收口到管理员

**Files:**
- Modify: `apps/api/src/routes/export.ts`
- Test: `apps/api/src/routes/system.test.ts` 或新增 export 权限测试

**Rationale:** `/backup/full` 与 `/backup/trigger` 会读取数据库和文件备份，权限等级应与 `/system/backup` 一致，要求管理员。

- [ ] Step 1: 增加失败用例：普通用户调用 `/backup/full` 返回 403。
- [ ] Step 2: 增加失败用例：普通用户调用 `/backup/trigger` 返回 403。
- [ ] Step 3: 将相关路由从 `requireUserId` 调整为管理员权限校验。
- [ ] Step 4: 运行相关测试，确认管理员可用、普通用户被拒绝。

### Task 4: 前端书籍详情避免无效 bookId 拉取全量笔记/高亮

**Files:**
- Modify: `apps/web/src/hooks/use-notes.ts`
- Modify: `apps/web/src/components/book-detail-sheet/page.tsx`
- Test: `apps/web/src/lib/api.test.ts` 或新增 hook 级轻量测试

**Rationale:** `BookDetailSheet` 使用 `bookId ?? 0` 调用 `useNotes` / `useHighlights`，当前 hooks 没有 `enabled`，可能请求 `/notes?` 或 `/highlights?`，造成无意义全量请求。

- [ ] Step 1: 为 `useNotes`、`useHighlights` 增加可选 `enabled` 参数，默认保持现有行为。
- [ ] Step 2: 在 `BookDetailSheet` 中传入 `enabled: open && bookId > 0`。
- [ ] Step 3: 确保需要全量查询的阅读笔记页仍可不传 `bookId` 正常工作。
- [ ] Step 4: 运行 web 测试、类型检查。
