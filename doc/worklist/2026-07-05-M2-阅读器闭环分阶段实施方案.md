## 2. M2 总体目标

M2 完成后，系统应满足以下最小闭环：

1. 用户从书籍进入阅读器。
2. 用户翻页后退出，再次进入时能回到原位置。
3. 用户在阅读器内可创建高亮、划线、附注、独立笔记。
4. 用户可从阅读痕迹列表跳回原文定位。
5. 用户可在单书范围和全局范围查看阅读痕迹。
6. 用户可导出单书笔记与高亮。

以下能力不属于本轮 M2 闭环范围：

- 朗读、TTS、整本全文检索、专注模式、字体主题增强
- 阅读统计增强
- 主题阅读深度能力（M4 主线）
- AI 阅读辅助（M3 主线）

## 3. 分阶段方案

### 阶段 A：阅读进度主链路先闭环

### 目标

先让“打开书 -> 阅读 -> 退出 -> 回到原位置”成立。这是 M2 的第一优先级，因为它是后续所有阅读留痕的基础锚点。

### 具体事项

- 新增 `reading_progress` 表 schema，并接入 Drizzle 导出
- 增加数据库迁移，包含唯一约束、按 `owner_id + last_read_at` 的索引
- 新增阅读进度接口：
  - `GET /books/{id}/reading-progress`
  - `PUT /books/{id}/reading-progress`
- 进度记录字段至少包含：
  - `book_id`
  - `owner_id`
  - `file_id`
  - `cfi`
  - `percentage`
  - `last_read_at`
- 在阅读器 `relocated` 事件中节流保存当前位置
- 首次打开阅读器时优先读取已保存进度并定位
- 当主阅读文件被替换或切换时，明确进度与 `file_id` 的兼容规则
- 详情页“阅读进度”显示改为读取真实 `reading_progress`，不再依赖伪进度
- 概览页“最近阅读”接入真实最近阅读数据

### 完成标志

- 一本书关闭后再次打开，能稳定回到上次阅读位置
- 详情页和概览页显示的阅读进度、最近阅读来源一致

### 实施记录（2026-07-05 已完成）

**数据层：**

- `packages/db/src/schema/reading-progress.ts` — 新增 `reading_progress` 表，字段：`id`, `book_id`, `owner_id`, `file_id`, `cfi`, `percentage`, `last_read_at`, `created_at`, `updated_at`
- 唯一约束：`uq_reading_progress_book_owner` ON (`book_id`, `owner_id`) — 每本书每人一条进度
- 普通索引：`idx_reading_progress_owner_last_read` ON (`owner_id`, `last_read_at`) — 概览页"最近阅读"查询
- `packages/db/drizzle/0015_reading_progress.sql` — 迁移文件
- `packages/db/src/schema/index.ts` — 已导出 `reading-progress`

**Shared 层：**

- `packages/shared/src/schemas.ts` — 新增 `readingProgressSchema`（输出）、`updateReadingProgressSchema`（输入：`file_id`, `cfi`, `percentage`）

**API 层：**

- `apps/api/src/routes/reading-progress.ts` — 三个端点：
  - `GET /api/v1/books/:id/reading-progress` — 获取单书进度，无记录返回 `null`
  - `PUT /api/v1/books/:id/reading-progress` — upsert 进度（按 `book_id + owner_id` 唯一键）
  - `GET /api/v1/reading-progress/recent` — 最近阅读列表（按 `last_read_at` 降序，限 5 条）
- `apps/api/src/server.ts` — 已注册 `readingProgressRoutes`

**前端层：**

- `apps/web/src/lib/api.ts` — 新增 `api.put` 方法
- `apps/web/src/hooks/use-reading-progress.ts` — 新增 `useReadingProgress` hook
- `apps/web/src/routes/book-reader.tsx` — 阅读器进度闭环：
  - 首次打开时通过 `GET /books/:id/reading-progress` 获取已保存进度，`file_id` 匹配时用 `rendition.display(cfi)` 恢复位置
  - `relocated` 事件中节流（2 秒）保存当前位置（cfi + percentage），通过 `PUT` 接口持久化
  - 相同位置不重复保存（`lastSaveRef` 去重）
  - 文件切换时 `file_id` 不匹配则跳过恢复，从头开始
- `apps/web/src/components/book-detail-sheet/page.tsx` — 详情页阅读进度改为读取 `reading_progress.percentage`，不再使用伪进度（原 `READ → 100%` 逻辑已移除）
- `apps/web/src/routes/overview.tsx` — 概览页"最近在读"改为展示 `reading_progress.percentage` 百分比
- `apps/api/src/routes/overview.ts` — 概览 API 的 `recent_reading` 改为从 `reading_progress` 表 JOIN `books` 查询，按 `last_read_at` 降序

**文件兼容规则：**

- 进度记录绑定 `file_id`（主 EPUB 文件 ID）
- 恢复时若 `file_id` 与当前主文件不匹配，不恢复旧 CFI（避免 CFI 失效）
- 文件替换后旧进度自然失效，新阅读产生新进度记录（upsert 覆盖）

### 阶段 B：阅读器内高亮 / 划线闭环

### 目标

把当前独立存在的 `highlights` 表和接口，真正接到阅读器选区交互上，形成“读的时候就能留痕”。

### 具体事项

- 设计阅读器内选区工具条交互：
  - 高亮
  - 划线
  - 添加附注
- 明确 `epub.js` 选区转 CFI 的实现方式
- 创建高亮时同时保存：
  - `cfi_start`
  - `cfi_end`
  - `text`
  - `type`
  - `color`
  - `note`
  - `mark_type`
- 明确原文兜底策略：
  - CFI 是主锚点
  - `text` 是显示与排障兜底
- 阅读器打开时加载当前书全部高亮并重绘
- 实现高亮点击查看与编辑附注
- 实现高亮删除
- 统一颜色、类型、标记类型的枚举与前端展示
- 校正当前高亮接口路径与《API接口》定义不一致的问题，决定是否保留全局接口、补充按书接口，或统一为一套正式契约

### 完成标志

- 用户在阅读器中框选文本后可立即生成高亮
- 刷新或重新打开后，高亮仍能正确重绘
- 高亮可查看、修改附注、删除

### 实施记录（2026-07-05 已完成）

**新增组件：**

- `apps/web/src/components/highlight-toolbar/index.tsx` — 浮动选区工具条，支持 4 种颜色（黄/蓝/绿/粉）的高亮、划线、附注
- `apps/web/src/components/highlight-note-editor/index.tsx` — 高亮点击后的附注编辑弹窗，支持标记类型（无标记/重要/疑问/洞见）、附注文本、删除

**阅读器改造：**

- `apps/web/src/routes/book-reader.tsx` — 完整高亮闭环：
  - 选区检测：通过 `rendition.hooks.content` 在 iframe 内监听 `mouseup`，获取 `Selection` 和 `Range`
  - CFI 生成：使用 `EpubCFI(range, baseCfi)` 将 DOM Range 转为 epubcfi 字符串
  - 创建高亮：通过 `useCreateHighlight` 调用 `POST /highlights`，传入 `cfi_start/end`、`text`、`type`、`color`
  - 重绘高亮：`renderHighlights()` 函数遍历 `highlights.data`，调用 `rendition.annotations.highlight()` / `underline()` 逐条渲染，`clear()` 清除旧注释
  - 点击交互：annotations 回调中弹出 `HighlightNoteEditor`，支持修改附注/标记/删除
  - 重新渲染：创建/更新/删除成功后自动 `refetch` + `renderHighlights()`

**API 契约校正：**

- `doc/API接口.md` — 高亮接口路径从 `/books/{id}/highlights` 统一为 `/highlights`（支持 `?book_id=X` 按书筛选），匹配实际实现

**设计决策：**

- CFI 是主锚点，`text` 是显示与排障兜底
- 颜色映射：`HIGHLIGHT` 用 `background-color: ${color}40`（半透明），`UNDERLINE` 用 `border-bottom: 2px solid ${color}`
- CFI 生成失败时工具栏不显示，静默处理
- 高亮渲染失败（CFI 失效）时跳过该条，不影响其他高亮
- 高亮接口保留全局设计（`/highlights`），通过 `?book_id=X` 参数按书筛选，比按书路径更灵活

### 阶段 C：独立笔记闭环

### 目标

让笔记不再只是“读书笔记页上的孤立表单”，而是成为阅读器中的正式产物。

### 具体事项

- 明确笔记模型边界：
  - 关联原文位置的笔记
  - 不关联原文位置的独立笔记
- 修正当前“无书籍笔记”前后端不一致问题
  - 当前前端允许 `book_id=0`
  - 当前后端要求 `book_id` 必须对应真实书籍
- 选择本轮正式策略：
  - 方案一：M2 仅允许“从属某本书”的笔记
  - 方案二：支持“全局独立笔记”，并同步扩展 schema 与接口约束
- 在阅读器内增加“添加笔记”入口：
  - 基于当前阅读位置创建笔记
  - 基于选区创建带引用的笔记
- 若继续采用 TipTap，补上编辑器接入；若本轮先不上 TipTap，则明确临时文本方案与后续升级路径
- 保证 `content_html` / `content_markdown` 的写入规则一致
- 阅读笔记页改为面向真实阅读痕迹，不再只是聚合展示壳
- 实现笔记编辑、删除、按书筛选

### 完成标志

- 用户可在阅读器中创建并保存笔记
- 笔记在阅读笔记页中可见、可编辑、可删除
- 数据模型与前后端校验不再互相矛盾

### 实施记录（2026-07-05 已完成）

> **变更说明**：选区附注原依附于 `highlight.note`，现已改为独立 `notes` 记录。选区操作流程：框选 → 点击附注 → 保存时始终创建视觉高亮（`highlights` 表）；若填写了附注内容，则额外创建独立笔记（`notes` 表，含选中文本引用）。C 阶段缺口已补齐，通过全部验证。

**新增组件：**

- `apps/web/src/components/ui/dialog.tsx` — 基于 Radix UI Dialog 的 shadcn/ui 风格 Dialog 组件

**阅读器笔记面板：**

- `apps/web/src/routes/book-reader.tsx` — 阅读器内笔记主链路：
  - 新建笔记：`relocated` 事件中记录 `currentCfiRef`，点击"在当前页添加笔记"弹出表单（标题 + 内容），写入 `notes` 表
  - 编辑笔记：笔记列表的编辑按钮弹出编辑表单，调用 `useUpdateNote`
  - 删除笔记：点击删除按钮直接删除，调用 `useDeleteNote`

  - 选区附注：`HighlightToolbar` 的"添加附注"按钮保存时会先创建视觉高亮；若填写附注内容，再额外创建独立笔记（内容包含原文引用）

**阅读笔记页编辑/删除：**

- `apps/web/src/routes/reading-notes/index.tsx` — 阅读笔记页改为面向真实阅读痕迹：
  - 新增 `useUpdateNote`、`useDeleteNote` 导入与使用
  - 编辑对话框：基于 Dialog 组件的编辑表单（input + textarea + 保存按钮）
  - 删除确认对话框：温馨提示 + 确认删除按钮
- `apps/web/src/routes/reading-notes/components.tsx` — `ReadingNoteCard` 新增 `onEdit`、`onDelete` 属性

**设计决策：**

- 笔记采用纯文本临时方案（input + textarea），TipTap 编辑器后置升级
- 笔记内容写入 `content_markdown` 字段，`content_html` 留空（后续 TipTap 升级时双存）
- `book_id` 必须对应真实书籍，不允许 `book_id=0` 的独立笔记
- 笔记面板与 TOC 面板互斥切换
- 选区附注不再只依附于高亮表：保存附注时会保留视觉高亮；若填写附注内容，再创建独立 `notes` 记录，满足“基于选区创建带引用笔记”的阶段目标

### 阶段 D：从痕迹跳回原文

### 目标

建立“笔记 / 高亮 -> 阅读器定位”的回跳能力，使沉淀内容可以重新进入阅读上下文。

### 具体事项

- 约定阅读器定位参数格式：
  - URL query
  - router state
  - 或统一的内部导航状态
- 实现从阅读笔记页跳转到阅读器并根据 `cfi` / `cfi_start` 定位
- 实现从高亮卡片跳转到阅读器并高亮目标片段
- 实现从详情页“阅读留痕”区跳入具体痕迹
- 处理目标文件缺失、CFI 失效、版本替换后的降级策略
- 对失效 CFI 提供可解释反馈，而不是静默失败

### 完成标志

- 点击笔记或高亮，可进入阅读器并尽量回到对应原文位置
- 定位失败时有明确降级提示

### 实施记录（2026-07-05 已完成）

**阅读器定位参数约定：**

- 采用 URL query 参数格式：`/books/{id}/read?cfi={cfi}`
- `cfi` 参数经过 `encodeURIComponent` 编码传递
- 无 CFI 时正常打开阅读器首页

**阅读器改造：**

  - 加载顺序：`?cfi=` 参数优先 → 已保存进度 → 首页
  - CFI 失效降级：`rendition.display()` catch 中回退到已保存进度或首页，并显示 toast 提示

  - 笔记使用 `n.cfi`，高亮使用 `h.cfi_start` 作为定位锚点
  - 无 CFI 的痕迹正常打开阅读器首页
- `apps/web/src/routes/reading-notes/components.tsx` — `ReadingNoteCard` 新增 `onNavigate` 回调属性：
  - "回到书中"按钮绑定 `onClick={onNavigate}`，hover 时出现

**详情页阅读留痕：**

- `apps/web/src/components/book-detail-sheet/page.tsx` — 阅读留痕标签页接入真实数据：
  - 新增 `useNotes(bookId)`、`useHighlights(bookId)` 获取当前书痕迹
  - 合并笔记与高亮，按创建时间倒序排列，最多显示 20 条
  - 每条痕迹显示类型标识（笔记/高亮）、标题摘要、日期
  - hover 时出现"跳转"按钮，点击导航到阅读器定位
  - 无痕迹时显示空状态提示

**降级策略：**

- `?cfi=` 定位失败 → 显示 toast 提示"未能定位到原文位置，已跳转至最近阅读位置"，自动回退到已保存阅读进度
- 已保存进度也失败 → 从书籍首页开始
- 无 CFI 痕迹直接打开阅读器首页

### 阶段 E：单书痕迹汇总与入口收口

### 目标

把当前分散的阅读能力收口到书籍详情、书架入口、阅读笔记页三处主入口中，避免用户面对割裂状态。

### 具体事项

- 书籍详情页“阅读留痕”区接入真实数据：
  - 最近进度
  - 高亮数量
  - 笔记数量
  - 最近痕迹列表
- 书架列表入口状态统一：
  - 已有可读 EPUB 时允许进入阅读器
  - 不再保留“阅读器将在 M2 上线”的旧文案
- 统一书架卡片、详情页、阅读页的阅读状态文案
- 阅读笔记页支持按书筛选、按时间排序、空状态说明
- 如果本轮不接主题能力，则“加入话题”按钮改为禁用说明或后置入口，不保留误导性交互

### 完成标志

- 用户从书架、详情页、阅读笔记页进入 M2 的路径一致
- 页面文案与真实能力一致，不再出现“可用/不可用”混杂状态

## 4. 推荐实施顺序

建议按以下顺序推进，而不是并行散做：

1. 阶段 A：先打通阅读进度
2. 阶段 B：再打通阅读器内高亮
3. 阶段 C：再打通笔记模型与阅读器笔记
4. 阶段 D：补回跳原文
5. 阶段 E：收口页面入口与详情聚合
6. 阶段 F：最后补搜索与导出

原因如下：

- 进度持久化是阅读器最基础的可信能力
- 高亮和笔记都依赖稳定的 CFI 与阅读上下文
- 回跳原文必须建立在高亮/笔记已稳定产出之后
- 搜索与导出属于闭环的尾部能力，不应阻塞阅读器主链路

## 6. 当前阶段最该先解决的现实问题

如果只选一个 M2 起点，优先做以下组合：

1. `reading_progress` 数据层与接口
2. 阅读器定位保存/恢复
3. 详情页与概览页接入真实阅读进度

这是最小但真实的 M2 起步包。它的价值是：

- 能把阅读器从“能打开”提升到“能持续使用”
- 不依赖高亮、TipTap、全文搜索等高风险项
- 做完后可以明确区分“阅读器基本可用”和“留痕增强继续推进”

## 7. 风险点

- `epub.js` 选区、CFI、重绘在不同 EPUB 上的稳定性需要专项验证
- 文件替换后，旧 CFI 是否仍可定位，需要定义降级策略
- 当前 `notes/highlights` 已上线为全局接口，是否要回收到按书接口，需要先统一契约
- 当前阅读笔记页、阅读话题页并非纯占位，改造时要避免与现有数据链路打架
- 独立笔记是否允许脱离书籍，是一个产品边界问题，必须先定

## 8. 建议的执行边界

本轮 M2 建议只承诺以下交付边界：

- 基础 EPUB 阅读
- 进度持久化
- 高亮 / 划线 / 附注
- 独立笔记
- 痕迹列表
- 跳回原文
- 搜索与导出

不在本轮承诺以下增强项：

- 书签体系扩展
- 阅读器个性化高级设置
- 阅读统计增强
- 主题阅读深度整合
- AI 阅读辅助

## 9. 结论

当前仓库最合理的 M2 拆法，不是按“功能点列表平均推进”，而是按“阅读主链路闭环程度”推进：

- 第一阶段先让用户能稳定接着读
- 第二阶段让用户在读的时候自然产生痕迹
- 第三阶段让痕迹能回到原文
- 第四阶段再补检索、导出和页面收口

这样可以最大限度复用当前已经存在的代码，而不是推翻重做。
