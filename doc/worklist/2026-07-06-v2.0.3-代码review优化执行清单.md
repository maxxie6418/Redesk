## 1. 总体判断

当前代码已经完成 M1/M2/M3 的主要功能闭环，项目不属于“功能缺失型”问题，而是进入了功能闭环后的结构治理阶段。主要问题集中在以下几类：

1. 重复实现已经出现分叉风险，尤其是书籍元数据抓取逻辑。
2. 部分文档宣称闭环的功能在代码中仍有占位逻辑，尤其是话题工作区跳回原文。
3. 少数接口存在 N+1 查询或分页策略粗放问题。
4. 阅读器、书籍、文件等核心模块文件体量偏大，后续迭代风险较高。
5. 调试日志、随机 key 生成、统一错误处理等工程质量项需要收紧。
6. shared schema 单文件持续膨胀，后续维护成本会继续上升。

本清单按优先级拆成 P0/P1/P2/P3 四组。P0/P1 建议优先连续处理；P2/P3 可在功能稳定后逐步治理。

---

## 2. 执行分组与验收口径

### P0：确定缺陷与宣称不一致项

目标：修复明确问题，消除“代码实际行为”和“当前版本状态宣称”之间的偏差。

### P1：高风险结构债务

目标：降低后续改动出错概率，优先处理重复实现、N+1 查询、核心大文件。

### P2：工程质量与性能优化

目标：提升稳定性、可观测性、数据规模增长后的体验。

### P3：长期可维护性整理

目标：拆分共享 schema、统一 UI 基础组件、改善迁移与文档治理。
