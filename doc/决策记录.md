## 3. 决策记录

### 2026-06-27 / 产品定位

- 结论：Redesk 定义为个人知识书库系统；书架管理、阅读与笔记、AI 协同知识系统共同构成完整产品。
- 影响范围：需求总纲、功能结构、后续模块命名。
- 备注：不再以“单纯书架工具”或“阅读器产品”定义项目。

### 2026-06-27 / 产品层次

- 结论：书架管理是基础层，阅读与笔记是沉淀层，AI 协同是增强层。
- 影响范围：产品叙述、模块分组、后续设计入口。
- 备注：阶段开发不得反向改变该层次。

### 2026-06-27 / 阅读定位

- 结论：在线阅读属于附属但重要能力，不作为产品核心竞争方向。
- 影响范围：阅读模块、格式支持、资源投入边界。
- 备注：阅读能力用于产生阅读痕迹和支持知识沉淀。

### 2026-06-27 / 文件支持

- 结论：EPUB 为首要阅读格式；非 EPUB 文件允许上传、存档和下载，不要求在线阅读。
- 影响范围：文件管理、阅读模块、导出与下载。
- 备注：文件管理价值独立成立，不依赖在线阅读能力。

### 2026-06-27 / 书籍与文件关系

- 结论：一本书允许关联多个文件，并允许指定一个主阅读文件。
- 影响范围：书籍模型、文件模型、阅读入口。
- 备注：第一阶段交互可收敛，模型不写死为单文件。

### 2026-06-27 / 可见性形态

- 结论：当前采用单书库视角，每本书设置公开或私有；不在当前阶段建立完整多书库模型。
- 影响范围：可见性、权限、书架组织。
- 备注：后续保留向多书库演进空间。

### 2026-06-27 / 状态体系

- 结论：书籍状态采用“收录 / 计划读 / 在读 / 已读 / 存档”。
- 影响范围：书籍管理、筛选、概览、导出。
- 备注：“存档”为正式业务状态，不得实现为删除或归档。

### 2026-06-27 / 阅读目的

- 结论：系统保留阅读目的或阅读方式表达，如泛读、精读、系统阅读、主题阅读。
- 影响范围：书籍语义、后续阅读组织方式。
- 备注：当前先确认产品方向，不锁定字段设计。

### 2026-06-27 / 主题阅读

- 结论：主题不是标签，至少是独立对象；长期可演进为工作区。
- 影响范围：主题模块、书籍关系、阅读痕迹组织、AI 设计。
- 备注：主题可以从一本书发起，也可以从多本书抽象形成。

### 2026-06-27 / 主题与书籍关系

- 结论：一本书可以属于多个主题，一个主题也可以关联多本书。
- 影响范围：主题模型、书籍模型、跨书组织。
- 备注：不采用“一书一主题”限制。

### 2026-06-27 / 主题与阅读痕迹关系

- 结论：阅读痕迹独立管理，主题按需引用和组合，不拥有原始阅读痕迹。
- 影响范围：笔记、高亮、主题、AI 派生内容。
- 备注：主题是重组和再利用层，不是原始数据归属层。

### 2026-06-27 / AI 定位

- 结论：AI 定位为陪读助手与辅助思考者，不仅是书籍管理助手。
- 影响范围：AI 模块、后续接口设计、主题阅读、知识沉淀。
- 备注：AI 长期目标是基于个人阅读经历提供辅助分析。

### 2026-06-27 / AI 读取边界

- 结论：AI 数据访问采用分级访问原则，后续可覆盖元数据、阅读痕迹和正文片段。
- 影响范围：AI 数据边界、隐私、权限。
- 备注：当前仅确认方向，具体分级策略后续规划。

### 2026-06-27 / AI 结果保存

- 结论：AI 生成内容可以保存回系统，但必须与用户原始内容区分。
- 影响范围：AI 派生内容、主题、笔记系统。
- 备注：后续需要单独规划展示与管理方式。

### 2026-06-27 / AI 引用依据

- 结论：AI 回答应尽量可追溯，当前至少关联到书和章节。
- 影响范围：AI 回答展示、主题分析、问答能力。
- 备注：如可关联高亮或笔记，作为增强能力处理。

### 2026-06-27 / 概览面板

- 结论：概览能力定位为书架概览，不定义为独立 BI 产品。
- 影响范围：首页、统计展示、模块边界。
- 备注：当前只确认定位，不锁定具体指标集合。

### 2026-06-27 / 数据资产

- 结论：核心数据资产包括书架元数据、阅读痕迹和书籍文件。
- 影响范围：导出、备份、数据模型、AI 输入范围。
- 备注：阅读经历被视为与书籍同等重要的长期资产。

### 2026-06-27 / 导出与备份

- 结论：系统必须支持导出与手动备份；批量打包和云备份不作为当前强制边界。
- 影响范围：导出模块、备份模块、数据主权说明。
- 备注：导出与备份属于产品可信度的一部分。

### 2026-06-27 / 技术路线

- 结论：暂定采用全栈 TypeScript 路线（Route A）：Node + Fastify + better-sqlite3 + Drizzle 后端，Vite + React + shadcn/ui 前端，SQLite 单文件存储（FTS5 全文检索 + sqlite-vec 向量检索），epub.js 阅读器，自托管 Docker 部署。
- 影响范围：后端栈、前端栈、数据存储、阅读器、AI 集成方式、部署形态。
- 备注：选型主因为"选错最好补救"——AI 最终形态未定型，Route A 可在必要时加 Python RAG 边车而主应用不动；非"技术理论最优"。AI 能力统一收敛在 `AIService` 接口后。详见《技术方案》。

### 2026-06-27 / 云同步方案

- 结论：云同步优先采用应用内置 S3 兼容对象存储同步（阿里云 OSS / AWS S3 / Cloudflare R2 / MinIO / B2），用户在设置页填写 endpoint/bucket/key/secret 即可；只同步书籍文件与 SQLite 备份副本，不同步在线数据库。rclone / Google Drive / Dropbox 后置为可选项。
- 影响范围：第三方集成模块（功能清单 8.05/8.06 调整）、设置页、备份与数据主权。
- 备注：S3/OSS 是内置优先路径，rclone 作为高级用户可选同步路径，不作为默认依赖；与"不默认强依赖云端"一致，云同步仍为可选增强。

### 2026-06-27 / owner_id 预留策略

- 结论：用户拥有的根实体表直接带 `owner_id`；从属关系表、历史表、引用表通过父表继承归属，不强制冗余 `owner_id`。
- 影响范围：数据模型、API 权限校验、查询约束。
- 备注：实现层查询从属表时必须 JOIN 父表或通过父资源路径校验 owner 边界；若未来出现跨用户共享或性能瓶颈，再评估冗余 `owner_id`。

### 2026-06-27 / 版本号规范

- 结论：所有文档与产物版本号采用三段式「主版本号.次版本号.修订号」。主版本号：阶段性更新修改时递增，须由用户声明后方可递增；次版本号：向下兼容的功能性新增时递增，由 AI 根据需求自动递增，但需向用户说明；修订号：向下兼容的问题修正时递增，由 AI 自动递增，无需说明。
- 影响范围：全部文档与代码产物的版本管理。
- 备注：既有两段式版本号（如 v1.0）统一迁移为三段式（如 v1.0.0），语义不变；历史修改记录同步改为三段式以保持一致。

## 4. 暂缓问题

### 2026-06-27 / AI 与原始内容的共存方式

- 结论：已确认必须区分，但暂不确定最终展示和管理方式。
- 影响范围：笔记系统、主题页面、AI 派生内容。
- 备注：后续单独展开。

### 2026-06-27 / 主题对象的最小字段

- 结论：确认主题是对象，但字段最小集合暂不锁定。
- 影响范围：主题模型、主题页面。
- 备注：后续根据产品结构单独确定。

### 2026-06-27 / 阅读目的的表达方式

- 结论：确认需要该能力，但是否按书籍级、阅读任务级或其他方式表达暂不锁定。
- 影响范围：书籍模型、主题阅读、阅读流程。
- 备注：当前先保留产品语义。

### 2026-06-28 / 鉴权模式

- 结论：鉴权不再由环境变量 `VITE_AUTH_DISABLED` 硬控制，改为 `settings` 表中 `multi_user` 键动态控制。`multi_user = "false"` 或不存时为单用户免登录模式，后端启动时自动创建默认管理员（admin/redesk），所有 API 自动使用管理员身份；`multi_user = "true"` 时开启密码登录，需通过 `/auth/login` 获取会话。环境变量 `AUTH_DISABLED` 保留为启动级硬开关（优先级最高），但日常使用通过设置页切换。
- 影响范围：鉴权路由（auth.ts）、授权中间件（lib/auth.ts）、设置页、前端入口探活（protected-layout.tsx）。
- 备注：单用户模式不再需要填写密码或 setup，开箱即用；开启多用户后用户管理 Tab 出现在设置页。

### 2026-06-28 / 设置存储

- 结论：所有应用配置用现有 `settings` 表（owner_id/key/value）存储，不做单独配置表。配置项按 key 读写，敏感字段（oss_access_key、oss_secret_key）回读脱敏。upsert 语义：PATCH /settings 对每个 key 存在则更新、不存在则插入。
- 影响范围：settings 路由、设置页、鉴权开关（multi_user 键）。
- 备注：当前配置项不超过 15 个，settings 表的 key-value 模型足够。后续如果有需要 DB 层类型约束的配置再评估迁表。

### 2026-06-28 / 分页上限

- 结论：`MAX_PAGE_SIZE` 从 100 上调至 500，以支持前端一次加载全部书籍列表（书架页无需分页翻页）。
- 影响范围：paginationSchema（packages/shared）、所有列表端点。
- 备注：前端书架页使用 page_size=200 请求全量数据，100 的限制导致 Zod 校验 400。500 对 SQLite 查询无性能压力。

### 2026-06-28 / 书架打磨阶段

- 结论：M1 书架与文件管理全部完成后，暂停向 M2 阅读器推进，先对书架管理进行体验打磨，目标是将基础层做到"称手"再开启沉淀层。打磨不改变 M1 的功能边界（不新增阅读器/AI 能力），但允许在书架管理范围内补充体验向功能点。
- 影响范围：开发节奏、功能清单（书架管理体验条目）、需求总纲（整理环节叙述）、M2 启动时机。
- 备注：打磨阶段的退出标准、具体优化清单、与 M2 的边界划分在 `doc/todo/M1-书架功能优化.md` 中展开讨论。打磨阶段允许小幅数据模型调整（如标签颜色、分类图标等字段），但不动核心表结构。

### 2026-06-28 / 重复检测算法

- 结论：M1 阶段采用纯规则版本：基于书名（权重 0.7）+ 作者（权重 0.3）的最长公共子串（LCS）算法计算相似度，阈值默认 0.6。不引入独立去重表，结果实时计算返回。AI 增强版（`/ai/duplicates`）留到 S3。
- 影响范围：GET /books/duplicates 端点实现、重复检测性能约束（O(n²) 逐对比较，适合中小规模书架）。
- 备注：该端点仅返回重复分组供用户人工判断，不做自动合并。

### 2026-06-28 / 文件管理

- 结论：文件上传使用 Fastify `@fastify/multipart` 插件，上限 200MB。文件存储在 `storage/books/{id}/` 下，路径以相对路径（相对于 storageDir）存入 book_files 表。一书支持多文件，通过 `is_primary` 标记主阅读文件。支持的范围格式：EPUB/PDF/MOBI/TXT/AZW3/AZW/DJVU/DOCX/FB2。
- 影响范围：files.ts 路由、book_files 表、storage 目录结构。
- 备注：文件替换保留原 book_files 记录（只更新元信息），不重建新记录。删除文件时同步删物理文件，若删除后该书无文件则清空 cover_path。

### 2026-06-28 / EPUB 封面抽取

- 结论：使用 adm-zip 解析 EPUB（实为 ZIP），按 META-INF/container.xml → OPF 文件 → `<meta name="cover">` → `<item href>` 查找封面图片，支持 fallback：匹配 entryName 中含 "cover" 且扩展名为图片的项。抽取后存入 `storage/covers/{bookId}/`，路径写入 books.cover_path。
- 影响范围：files.ts 封面抽取代码、GET /books/:id/cover 端点。
- 备注：EPUB 上传时自动触发抽取；`/books/:id/cover` 设置 Cache-Control 86400s。封面缺失时返回 404。

### 2026-07-02 / 系统管理权限收口（WL-001）

- 结论：`users.is_admin` 专用于系统管理权限判断，与 `owner_id` 资源归属完全分离。系统维护写接口（`/system/backup`、`/system/fts-rebuild`、`/system/clear-cache`、`/system/reset`）仅 `is_admin=1` 用户可访问；未登录返回 401，已登录非管理员返回 403；免登录模式（`VITE_AUTH_DISABLED=true` / `AUTH_DISABLED=true`）视为默认管理员会话，等价放行。`/system/stats`、`/system/storage` 登录用户可读，但 `/system/stats` 不再返回 `db_path` 绝对路径、`user_count` 仅对管理员返回；`/system/storage` 不暴露全库绝对路径或全局磁盘细节，仅返回用户范围汇总。本版本不开放"晋升 / 降级管理员"接口，维持单管理员语义。
- 影响范围：`apps/api/src/lib/auth.ts`（新增 `requireAdmin` / `isAdminRequest`）、`apps/api/src/routes/system.ts`（6 个端点鉴权与返回结构调整）、`doc/数据模型.md` §3.1.1（系统管理权限说明）、`doc/API接口.md` §12（权限说明与字段调整）。
- 备注：管理员不天然拥有跨用户数据访问权，资源级读写仍受 `owner_id` 约束。多用户阶段延续同一权限模型。

### 2026-07-02 / 书籍文件主文件升/降规则（WL-002）

- 结论：一本书还没有任何主文件时，新增的第一个关联文件**必须**自动设为主文件；已存在主文件时，**仅在显式传入 `is_primary=true` 时才切换**主文件；`is_primary=false` 或字段未传均表示"不切换主文件"，不会把当前主文件降为非主文件。multipart 中 `is_primary` 严格只接受字符串 `true` / `false`，不接受 `1` / `0` 或任意 truthy；非法值（如 `is_primary=foo`）返回 400，不允许静默吞掉。未关联文件（`/files/unassociated`）永远为非主文件；未关联文件关联到书籍（`/files/:id/match`、`/files/unassociated/:id/associate`）时同样遵守"无主则升、有主不动"规则。
- 影响范围：`apps/api/src/routes/files.ts`（`saveUploadedFile` 签名与升/降规则；新增 `readMultipartBool` / `applyPrimaryOnLink` 局部 helper；`/books/:id/files` 显式读取并校验 `is_primary`；`/files/:id/match` / `/files/unassociated/:id/associate` 调用升主 helper）、`doc/API接口.md` §4（端点字段语义更新）。
- 备注：补丁式主文件切换仍由 `PATCH /books/:id/files/:fileId` 走 Zod schema 校验处理（语义已正确，未变更）。前端 hook 继续使用 `isPrimary`，发送 multipart 时由前端负责转换为 `is_primary`，后端只接收 `is_primary`。

### 2026-07-02 / 文件替换接口语义（WL-003）

- 结论：保留"替换文件内容但保留记录"的能力，**后端补齐** `POST /books/:id/files/:fileId/replace` 路由，前后端契约一致。允许跨格式替换（如 `.epub` → `.pdf`），不限制只能替换主文件，主文件 / 非主文件均可替换，替换后**保持原身份不变**（`is_primary` 字段不因本接口变化）。校验值算法与 `files` 表现有算法一致（SHA-256，`writeStreamForMode` 内部计算）。事务采用"先新后旧"安全替换语义：写新文件到 `books/{bookId}/.tmp/replace-{fileId}-{ts}{ext}` 临时 key → DB 一次更新 metadata + path 指向正式 key → `storage.move` 临时 → 正式（覆盖）→ 删除旧物理文件（best-effort）。任一步失败回滚到旧 path 并清理临时文件，**不允许出现"DB 已指向新文件但新文件不可用"的半成功状态**。跨 owner / 不存在 / 已删 全部 404，避免泄露资源存在性。本版本替换接口**只处理文件资产**，不主动清理未来阅读留痕数据；留痕按 `book_id` 语义处理，本版本不引入 `file_id` 级失效逻辑。
- 影响范围：`apps/api/src/routes/files.ts`（新增 `replaceBookFile` 内部函数 + `POST /books/:id/files/:fileId/replace` 端点）、`doc/API接口.md` §5（替换接口契约）。
