# 书籍详情页 Notion 式原位编辑交互说明方案

> 适用范围：书籍详情页的“书籍档案”信息编辑体验。
>
> 目标：在不破坏当前详情页阅读与档案展示结构的前提下，让编辑模式支持更多字段、使用更合适的编辑控件，并确保所有临时编辑 UI 以浮层覆盖方式出现，不推挤其他页面内容。

## 1. 背景与现状问题

当前书籍详情页已支持部分字段编辑，但交互存在明显割裂：

1. 分类、状态、可见性等字段点击后会在原位置替换成原生下拉框，控件会参与页面布局，导致周围 UI 被推挤。
2. 原生下拉框样式与 Redesk 当前暖色、轻量、卡片化的视觉风格不一致。
3. 编辑范围有限，仅覆盖标题、作者、状态、分类、评分、阅读目的、可见性、来源链接、简介、自定义属性、标签等部分字段。
4. 保存触发方式不统一，部分字段依赖失焦保存，部分字段需要显式保存，部分字段点击即保存。
5. 详情页中已经存在大量逻辑，继续以零散内联方式增加字段会让维护成本继续上升。

本方案将编辑体验调整为类似 Notion 的“原位触发 + 浮层编辑”：用户仍在原详情布局中点击字段进行修改，但所有编辑器都覆盖在页面内容之上，不改变文档流，不挤压其他 UI。

## 2. 设计目标

### 2.1 用户体验目标

- 保持详情页原有信息结构，不切换到独立编辑页，也不打开单独的大型编辑面板。
- 编辑模式下，字段仍在原位置展示和触发。
- 弹出的选择框、输入框、多选器、长文本编辑器都以浮层覆盖方式出现。
- 字段类型不同，编辑方式不同，避免所有内容都用同一种控件处理。
- 用户能清楚知道哪些字段可编辑，空字段也能被发现并补充。
- 保存行为明确，避免误触、误保存、编辑中内容丢失。

### 2.2 技术与维护目标

- 以 `PATCH /books/{id}` 已支持的字段为主要覆盖范围。
- 不改变后端接口契约，优先通过前端组件重构改善体验。
- 拆分可复用的字段编辑组件，避免继续扩大详情页主组件复杂度。
- 保留 React Query 更新链路：保存成功后刷新单本详情与书架列表缓存。
- 保持当前项目 TypeScript 严格模式、snake_case API 字段、camelCase 前端状态的约定。

## 3. 总体交互模型

### 3.1 编辑模式入口

详情页默认保持只读展示。用户点击顶部“编辑”按钮后进入编辑模式。

进入编辑模式后：

- 页面布局不发生整体变化。
- 可编辑字段的值区域出现轻微 hover 态。
- 空值字段显示为“点击添加”。
- 鼠标悬停时可显示轻量编辑提示，例如浅色背景、边框或小编辑图标。
- 用户点击字段值后，根据字段类型打开对应浮层编辑器。

退出编辑模式后：

- 所有字段恢复纯展示状态。
- 已打开但未保存的浮层需要先处理未保存变更。
- 若有正在编辑且内容已修改，应提示用户保存或放弃。

### 3.2 浮层原则

所有临时编辑控件必须脱离正常文档流，覆盖在当前内容上方显示。

交互要求：

- 不使用会撑开字段行高度的原生内联下拉框。
- 不因为打开选择器、标签面板、长文本编辑器而推挤其他内容。
- 浮层应有合适的阴影、边框、圆角、背景色，与现有 Redesk UI 风格一致。
- 浮层宽度根据字段类型控制：短文本较窄，长文本较宽，标签面板可中等宽度。
- 浮层内部内容过长时，浮层内部滚动，而不是撑开详情页。
- 点击浮层外部时：
  - 单选类字段可直接关闭。
  - 输入类字段若有未保存修改，应阻止静默丢失，并提示保存或取消。

### 3.3 保存策略

字段按操作语义分为两类保存策略。

#### 点击即保存

适用于选择动作本身就是完整意图的字段：

- 状态
- 可见性
- 个人分类
- 常规分类
- 评分

用户点击选项后立即调用更新接口。保存成功后关闭浮层并刷新展示。保存失败时保留当前浮层或恢复原值，并显示错误反馈。

#### 显式保存

适用于需要输入、可能连续操作、或容易误触的字段：

- 文本字段
- 数字字段
- 日期字段
- 标签多选
- 长文本字段
- 自定义属性

浮层内提供“保存 / 取消”。短文本支持 Enter 保存、Esc 取消。长文本中 Enter 仅换行，Ctrl+Enter 保存，Esc 取消。

保存失败时浮层不关闭，用户输入不丢失，并在浮层内显示错误原因。

## 4. 字段覆盖范围

普通编辑模式覆盖 `PATCH /books/{id}` 中适合用户直接编辑的字段。

### 4.1 基础信息

| 字段 | API 字段 | 编辑方式 | 保存策略 |
| --- | --- | --- | --- |
| 书名 | `title` | 短文本浮层 | 显式保存 |
| 副标题 | `subtitle` | 短文本浮层 | 显式保存 |
| 作者 | `author` | 短文本浮层 | 显式保存 |
| 译者 | `translator` | 短文本浮层 | 显式保存 |
| 原书名 | `original_title` | 短文本浮层 | 显式保存 |
| ISBN | `isbn` | 短文本浮层 | 显式保存 |

### 4.2 出版与来源

| 字段 | API 字段 | 编辑方式 | 保存策略 |
| --- | --- | --- | --- |
| 出版社 | `publisher` | 短文本浮层 | 显式保存 |
| 出版年份 | `publish_year` | 数字输入浮层 | 显式保存 |
| 语言 | `language` | 短文本浮层 | 显式保存 |
| 页数 | `page_count` | 数字输入浮层 | 显式保存 |
| 来源链接 | `source_url` | 短文本浮层 | 显式保存 |

### 4.3 书架管理

| 字段 | API 字段 | 编辑方式 | 保存策略 |
| --- | --- | --- | --- |
| 状态 | `status` | 浮层选择菜单 | 点击即保存 |
| 可见性 | `visibility` | 浮层选择菜单 | 点击即保存 |
| 个人分类 | `category_id` | 浮层选择菜单 | 点击即保存 |
| 常规分类 | `genre_category_id` | 浮层选择菜单 | 点击即保存 |
| 标签 | `tag_ids` | 浮层多选面板 | 显式保存 |
| 评分 | `rating` | 原位星级选择 | 点击即保存 |

### 4.4 阅读信息

| 字段 | API 字段 | 编辑方式 | 保存策略 |
| --- | --- | --- | --- |
| 阅读目的 | `reading_purpose` | 长文本浮层 | 显式保存 |
| 开始阅读时间 | `started_at` | 日期输入浮层 | 显式保存 |
| 完成阅读时间 | `finished_at` | 日期输入浮层 | 显式保存 |

### 4.5 内容与扩展

| 字段 | API 字段 | 编辑方式 | 保存策略 |
| --- | --- | --- | --- |
| 简介 | `description` | 长文本浮层 | 显式保存 |
| 自定义属性 | `custom_attributes` | JSON 文本浮层 | 显式保存 |

### 4.6 不暴露字段

`metadata_source` 暂不在普通编辑模式中暴露。它更接近系统来源字段，不属于用户日常维护书籍档案时的自然编辑项。

## 5. 字段编辑器说明

### 5.1 短文本浮层

适用于书名、副标题、作者、译者、原书名、ISBN、出版社、语言、来源链接。

交互：

1. 用户点击字段值。
2. 字段附近弹出输入浮层。
3. 输入框自动聚焦并选中当前文本。
4. 用户可按 Enter 保存，Esc 取消。
5. 点击“保存”提交更新。
6. 点击“取消”关闭浮层并恢复原值。

校验：

- 书名不能为空。
- 文本长度遵循后端 schema 限制。
- 来源链接可为空；第一版不强制 URL 格式，只遵循长度约束。

### 5.2 数字输入浮层

适用于出版年份、页数。

交互：

1. 用户点击字段值或“点击添加”。
2. 弹出数字输入浮层。
3. 用户输入数字并保存。
4. 支持一键清空，将值保存为 `null`。

校验：

- 出版年份必须为 0 到 2100 的整数，或为空。
- 页数必须为非负整数，或为空。

### 5.3 浮层选择菜单

适用于状态、可见性、个人分类、常规分类。

交互：

1. 用户点击当前值。
2. 弹出选项菜单。
3. 当前选项有选中态。
4. 用户点击某个选项后立即保存。
5. 保存成功后关闭菜单。
6. 保存失败时显示错误反馈。

分类菜单要求：

- 个人分类支持“未分类”。
- 常规分类支持“未分类”。
- 分类列表来自对应分类查询结果。
- 第一版可不做搜索；如果分类数量较多，后续升级为带搜索的 Command 菜单。

### 5.4 标签多选浮层

适用于标签。

交互：

1. 用户点击标签区域。
2. 弹出标签多选面板。
3. 面板中展示全部标签。
4. 已选标签使用高亮 chip 样式。
5. 用户可连续选择或取消多个标签。
6. 点击“保存”后一次性提交 `tag_ids`。
7. 点击“取消”放弃本次修改。

空状态：

- 当前书籍无标签时，字段展示“点击添加标签”。
- 系统无任何标签时，浮层展示空状态提示，不在本次方案中新增标签创建能力。

### 5.5 评分编辑

适用于评分。

交互：

1. 编辑模式下，评分星级在原位置可点击。
2. 点击 1 到 5 星后立即保存。
3. 提供清空评分入口。
4. 保存中可临时禁用重复点击。

### 5.6 日期输入浮层

适用于开始阅读时间、完成阅读时间。

交互：

1. 用户点击日期字段。
2. 弹出日期输入浮层。
3. 用户选择或输入日期。
4. 保存时转换为 ISO 8601 UTC 字符串提交。
5. 支持清空日期，将值保存为 `null`。

校验：

- 日期输入为空时表示清空。
- 非法日期不允许保存。
- 不强制开始时间早于完成时间，避免阻断用户补录历史数据；后续可根据产品需要增加轻提示。

### 5.7 长文本浮层

适用于简介、阅读目的。

交互：

1. 用户点击文本区域。
2. 弹出较宽的 textarea 浮层。
3. 浮层内部可滚动。
4. Ctrl+Enter 保存，Esc 取消。
5. 底部固定显示“保存 / 取消”。

校验：

- 简介最大长度遵循后端限制。
- 阅读目的最大长度遵循后端限制。

### 5.8 自定义属性 JSON 浮层

适用于自定义属性。

交互：

1. 用户点击自定义属性区域。
2. 弹出 JSON 文本编辑浮层。
3. 当前值格式化显示为缩进 JSON。
4. 用户编辑后点击保存。
5. 保存前在前端执行 `JSON.parse`。
6. 解析失败时在浮层内显示错误，不关闭浮层。
7. 内容为空时保存为 `null`。

第一版不实现键值对编辑器，以降低范围和复杂度。后续如果用户高频使用自定义属性，可再升级为键值表格式编辑。

## 6. 视觉与状态规范

### 6.1 可编辑态

编辑模式下，可编辑字段应具备统一视觉提示：

- hover 时出现浅色背景。
- 圆角与详情页卡片风格一致。
- 空值使用较浅颜色展示“点击添加”。
- 当前正在保存的字段显示 loading 或禁用态。
- 保存失败后保留用户输入，并显示错误提示。

### 6.2 只读态

只读态不显示编辑提示，不改变当前详情页阅读体验。

字段为空时仍可显示 `—` 或当前已有的空值样式。只有编辑模式下才显示“点击添加”。

### 6.3 浮层样式

浮层应统一使用：

- 背景色：与当前卡片或弹窗背景一致。
- 边框：使用项目当前 `border` 风格。
- 阴影：轻量阴影，表达覆盖层级。
- 圆角：与现有按钮、卡片一致。
- 层级：高于详情页内容，低于全局确认弹窗。

### 6.4 键盘行为

- Enter：短文本、数字、日期保存。
- Ctrl+Enter：长文本保存。
- Esc：取消当前浮层。
- Tab：在当前浮层内自然移动焦点，不跳到被覆盖的底层内容。

## 7. 技术实现建议

### 7.1 组件拆分

建议在 `apps/web/src/components/book-detail-sheet/` 下拆分编辑相关组件，避免继续扩大详情页主组件。

建议组件：

- `editable-field.tsx`：字段展示、触发、浮层定位、基础交互。
- `editable-text-field.tsx`：短文本编辑。
- `editable-select-field.tsx`：单选菜单编辑。
- `editable-number-field.tsx`：数字编辑。
- `editable-date-field.tsx`：日期编辑。
- `editable-long-text-field.tsx`：长文本编辑。
- `editable-tags-field.tsx`：标签多选编辑。
- `editable-json-field.tsx`：自定义属性 JSON 编辑。

如果首轮实现希望减少文件数量，可以先合并为较少的内部组件，但不建议继续全部堆在 `page.tsx`。

### 7.2 浮层实现

当前项目未发现现成 Popover 或 Command 组件。第一版可以使用 React 状态配合绝对定位浮层实现：

- 字段触发器使用 `position: relative` 包裹。
- 浮层使用 `position: absolute`，从而脱离文档流。
- 对于详情页边界不足的场景，通过右对齐、最大宽度、最大高度和内部滚动处理。
- 后续如果引入 Radix Popover 或 shadcn Popover，需要先确认依赖与项目组件规范。

### 7.3 数据更新

继续使用现有 `useUpdateBook`：

- 单字段保存时只提交当前字段 payload。
- 标签保存时提交完整 `tag_ids`。
- 自定义属性保存时提交对象或 `null`。
- 保存成功后沿用 React Query 失效缓存逻辑，刷新单本详情和书架列表。

### 7.4 字段转换

前端展示状态使用 camelCase，提交给 API 时使用 snake_case。

转换规则：

- 空字符串转为 `null`，书名除外。
- 数字字段空值转为 `null`，非空时转为 Number。
- 日期字段空值转为 `null`，非空时转为 ISO 字符串。
- 自定义属性空值转为 `null`，非空时解析为对象。
- 分类空值转为 `null`。

## 8. 实施顺序建议

### 第一阶段：修复当前最不优雅的选择类编辑

目标：消除原生下拉框和布局推挤。

范围：

- 状态
- 可见性
- 个人分类
- 常规分类

产出：

- 原字段位置点击触发浮层选择菜单。
- 选择菜单覆盖显示，不挤压 UI。
- 点击选项即保存。
- 样式与详情页一致。

### 第二阶段：补齐基础字段与数字日期字段

目标：让书籍详情页支持主要元数据编辑。

范围：

- 书名
- 副标题
- 作者
- 译者
- 原书名
- ISBN
- 出版社
- 出版年份
- 语言
- 页数
- 来源链接
- 开始阅读时间
- 完成阅读时间

产出：

- 文本、数字、日期字段都可原位触发浮层编辑。
- 保存与校验行为统一。

### 第三阶段：完善复杂字段编辑

目标：覆盖长文本、多选与扩展属性。

范围：

- 标签
- 评分
- 阅读目的
- 简介
- 自定义属性

产出：

- 标签使用浮层多选。
- 长文本使用浮层 textarea。
- 自定义属性使用 JSON 浮层编辑并提供解析错误提示。

## 9. 验收标准

完成后应满足以下标准：

1. 进入编辑模式后，详情页布局不发生可见跳动。
2. 分类、状态、可见性、常规分类的选择菜单不再推挤其他 UI。
3. 不再在详情页档案区使用未包装的原生下拉编辑控件。
4. 所有用户可编辑字段均能通过详情页编辑模式修改。
5. 文本、数字、日期、长文本、标签、自定义属性分别使用符合字段语义的编辑方式。
6. 单选类字段点击选项即保存。
7. 输入类字段显式保存，失败时不丢失输入。
8. 自定义属性 JSON 格式错误时不能提交，并在浮层内提示。
9. 保存成功后详情页与书架列表数据刷新。
10. `pnpm typecheck` 与 `pnpm lint` 通过。

## 10. 暂不包含范围

以下内容不在本次交互改造中实现：

- 新增标签创建能力。
- 分类管理能力。
- 自定义属性键值表格式编辑器。
- `metadata_source` 手动编辑。
- 后端 API 契约变更。
- 批量编辑书籍。
- 移动端专用重排方案。

这些能力可在后续独立设计和实现。
