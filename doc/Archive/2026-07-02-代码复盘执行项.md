## WL-001 系统维护接口权限收口

- 优先级：P1
- 类型：安全 / 权限边界
- 背景：
  - 当前系统维护型接口权限不一致。
  - `POST /system/clear-cache` 未做登录校验。
  - `POST /system/reset` 只校验当前用户密码，未校验管理员身份。
  - `POST /system/backup`、`POST /system/fts-rebuild` 也只有登录校验，没有管理员限制。
- 目标：
  - 所有系统维护型接口统一收口到"仅管理员可执行"。
  - 未登录与普通用户访问时返回一致且明确的错误。
- 涉及文件：
  - `apps/api/src/routes/system.ts`
  - `apps/api/src/lib/auth.ts`
  - `apps/api/src/lib/auth-context.ts`（待新建或重命名）
  - `packages/shared/src/errors.ts`（如需要）
  - `doc/数据模型.md`（增加系统管理权限章节）
  - `doc/API接口.md`（如接口契约变化）
  - `doc/决策记录.md`（新增红线条目）
- 拍板要点：
  - 管理员按 `users.is_admin` 定义；该字段已存在于 `users` 表，无需新增迁移。
  - `owner_id` 只表示资源归属，不参与系统管理权限判断。
  - 免登录模式（`VITE_AUTH_DISABLED=true`）下，鉴权层统一产出"当前有效用户上下文"并视作默认管理员会话；不把免登录判断散落到 `requireAdmin` 路由处理函数里。
  - 错误码：未登录 401；已登录但非管理员 403。
  - 权限矩阵：
    - 只读系统观测（`/system/stats`、`/system/storage`）：登录用户可访问，且返回值必须限制在当前用户可见范围内，不暴露全库绝对路径或全局磁盘细节。
    - 写系统维护：`/system/backup`、`/system/fts-rebuild`、`/system/clear-cache`、`/system/reset` 仅管理员可访问。
  - 本版本不做"晋升 / 降级管理员"接口；维持单管理员语义。
  - "登录可读"和"全局可读"的区别需写进 [决策记录](doc/决策记录.md)，避免后续误读。
- 建议动作：
  - 在 `apps/api/src/lib/auth.ts`（或新建 `auth-context.ts`）中实现统一的"当前有效用户上下文"预处理器：免登录模式下注入默认管理员视图。
  - 新增 `requireAdminUserId(req)` 工具函数，仅消费预处理器产出的上下文。
  - 在 `apps/api/src/routes/system.ts` 中对所有写接口统一加 `preHandler: [app.authenticate, requireAdmin]`；只读接口保留 `preHandler: [app.authenticate]`。
  - 复核 `/system/stats`、`/system/storage` 的查询 SQL，确保按 `owner_id` 范围过滤。
  - 同步更新 [数据模型.md](doc/数据模型.md) 增加"系统管理权限"章节。
  - 同步更新 [决策记录.md](doc/决策记录.md) 新增 WL-001 相关红线条目。
- 验收标准：
  - 未登录访问系统维护写接口返回 401。
  - 普通用户访问系统维护写接口返回 403。
  - 管理员访问行为保持正常。
  - 登录用户访问 `/system/stats`、`/system/storage` 正常，且返回值只包含当前用户范围数据。
  - 免登录模式下所有 `/system/*` 写接口均能正常通过。
  - 前端设置页无功能回归。
  - `pnpm typecheck` 与 `pnpm lint` 通过。

## WL-002 修正书籍文件上传默认覆盖主文件的问题

- 优先级：P2
- 类型：业务逻辑 / 文件管理
- 背景：
  - 当前关联到书籍的文件上传会默认把新文件设为主文件。
  - 这会导致一书多文件场景下，用户已有主阅读文件被新上传文件自动替换。
  - 前端 hook 已经预留 `isPrimary` 参数，但后端当前没有按该参数执行。
- 目标：
  - 上传书籍文件时，是否设为主文件由后端按明确规则处理。
  - 规则与产品语义一致：首文件自动主，已有主文件不轻易被覆盖。
- 涉及文件：
  - `apps/api/src/routes/files.ts`
  - `apps/web/src/hooks/use-files.ts`
  - 书籍详情文件上传 UI（如有）
  - `packages/shared/src/schemas.ts`（如需补 Zod 校验）
  - `doc/API接口.md`（行为变化需同步）
  - `doc/决策记录.md`（新增红线条目）
- 拍板要点：
  - 主文件升 / 降规则（写死，不再"可自动"）：
    - 一本书还没有任何主文件时，新增的第一个关联文件**必须**自动设为主文件。
    - 已存在主文件时，**仅在显式传入 `is_primary=true` 时才切换**主文件。
    - `is_primary=false` 或字段未传，均表示"不切换主文件"，不会把当前主文件降为非主文件。
  - 字段命名：
    - 前端 hook 继续用 `isPrimary`。
    - 发送 multipart 时前端负责把 `isPrimary` 转换为 `is_primary`。
    - 后端只认 `is_primary`，**不要把 camelCase 传到后端**。
  - 布尔值序列化：
    - multipart 中 `is_primary` 严格只接受字符串 `true` / `false`。
    - 不接受 `1` / `0`，不接受任意 truthy。
  - 非法值处理：
    - 收到非法值（如 `is_primary=foo`）必须返回 400，不允许静默吞掉。
  - 校验实现位置：
    - Fastify 解析 multipart 时显式读取并校验布尔值即可，不需要为 multipart 再额外建一层完整 schema。
  - 未关联文件匹配到书籍的路径也遵守同样规则：若目标书还没有主文件，匹配进去后自动升为主文件；已有主文件时仅在显式要求时才替换。
- 建议动作：
  - 后端在文件上传路由的 multipart 解析处显式读取 `is_primary`，做白名单布尔校验（接受 `true` / `false`，其他值返回 400）。
  - 业务逻辑按上面"主文件升 / 降规则"执行；旧的"上传即设主文件"默认行为移除。
  - 同步检查"未关联文件匹配到书籍"路径是否也走同样规则。
  - 必要时在 `packages/shared/src/schemas.ts` 增加 `isPrimary` → `is_primary` 的转换工具或类型别名。
  - 同步更新 [API接口.md](doc/API接口.md) 记录 `is_primary` 字段语义与允许值。
  - 同步更新 [决策记录.md](doc/决策记录.md) 新增 WL-002 相关红线条目。
- 验收标准：
  - 已有主文件的书再上传普通文件（不传或传 `is_primary=false`），不会自动覆盖主文件。
  - 显式指定 `is_primary=true` 时，旧主文件被正确降级。
  - 首次上传文件的书仍能正常得到主文件。
  - 收到 `is_primary=foo` 等非法值时返回 400。
  - 未关联文件匹配到书籍的逻辑与上面一致。
  - 文件列表、书籍详情页显示与实际状态一致。
  - `pnpm typecheck` 与 `pnpm lint` 通过。

## WL-003 清理或补齐失效的文件替换接口

- 优先级：P3
- 类型：接口一致性 / 技术债
- 背景：
  - 前端仍保留 `useReplaceFile()`，请求 `POST /books/:id/files/:fileId/replace`。
  - 后端当前没有对应路由，后续一旦接入此能力会直接 404。
  - 这属于"前端遗留契约"和"后端真实契约"不一致。
- 目标：
  - 补齐真实替换接口，前后端契约一致。
  - 替换行为安全、可回滚，不引入"半成功"状态。
- 涉及文件：
  - `apps/web/src/hooks/use-files.ts`（已有 `useReplaceFile`，需对齐后端契约）
  - `apps/api/src/routes/files.ts`（新增 `POST /books/:id/files/:fileId/replace`）
  - `packages/shared/src/schemas.ts`（必要时补 Zod schema）
  - `doc/API接口.md`（新增 / 更新替换接口契约）
  - `doc/决策记录.md`（新增红线条目）
- 拍板要点：
  - **保留**"替换文件内容但保留记录"的能力。
  - 允许跨格式替换（如 `.epub` → `.pdf`）。
  - 不限制只能替换主文件，主文件和非主文件都可替换。
  - 替换行为：
    - 保留原记录 ID（`file_id` 不变）。
    - 更新 `original_filename`、格式、文件大小、校验值、存储位置、`updated_at`。
    - 替换后保持原身份不变：主文件替换后仍为主文件，非主文件替换后仍为非主文件。
  - 校验值算法：与现有 `files` 表存储的算法保持一致。
  - 物理文件清理：替换成功后必须删除旧物理文件，避免孤儿文件残留。孤儿文件清理作为兜底机制，放到未来清理任务中。
  - 事务与回滚：采用"先新后旧"的安全替换语义，对外等价为原子替换：
    1. 新文件成功写入并校验通过；
    2. 再更新 DB 记录指向新文件；
    3. DB 提交后再删除旧物理文件。
    任一步失败则保留旧记录与旧文件，不允许"DB 已指向新文件但新文件不可用"的半成功状态。
  - 鉴权：跨 owner 操作返回 404（避免泄露资源存在性）。
  - 与阅读留痕的关系：本版本替换接口只处理文件资产，不主动清理未来阅读留痕数据。留痕按 `book_id` 语义处理，本版本不引入 `file_id` 级失效逻辑。
- 建议动作：
  - 后端补齐 `POST /books/:id/files/:fileId/replace` 路由，按上述"先新后旧"语义实现。
  - 校验 owner 边界（基于 `request.authContext`），跨 owner 返回 404。
  - 文件哈希算法与现有 `files` 表保持一致，不引入新算法。
  - 旧物理文件删除放在 DB 提交后；删除失败允许短期孤儿文件存在。
  - 同步更新 [API接口.md](doc/API接口.md) 记录替换接口契约与错误码。
  - 同步更新 [决策记录.md](doc/决策记录.md) 新增 WL-003 相关红线条目。
- 验收标准：
  - 仓库中不存在"前端调用但后端没有"的替换接口。
  - 文档、前端 hooks、后端 routes 三者一致。
  - 跨 owner 访问返回 404。
  - 主文件 / 非主文件均可替换，替换后身份不变。
  - 跨格式替换不报错，文件记录字段正确更新。
  - 失败时无"半成功"状态（旧记录与旧文件保留）。
  - `pnpm typecheck` 与 `pnpm lint` 通过。

## WL-005 统一页面外壳并收紧 Sidebar 的职责

- 优先级：P3
- 类型：结构规整 / 可维护性
- 背景：
  - 大部分页面已使用 `AppShell`。
  - 设置页仍直接拼接 `AppSidebar`，形成第二套布局写法。
  - `AppSidebar` 组件虽然接收 `user`，但内部又自行请求认证状态与初始化状态，职责过重。
- 目标：
  - 统一"页面壳层"的使用方式。
  - 让 `AppSidebar` 更偏展示和交互，不再承担过多认证查询逻辑。
- 涉及文件：
  - `apps/web/src/components/app-shell.tsx`
  - `apps/web/src/components/app-sidebar.tsx`
  - `apps/web/src/components/protected-shell.tsx`（待新建）
  - `apps/web/src/routes/settings.tsx`
  - `apps/web/src/routes/overview.tsx`
  - `apps/web/src/routes/file-library.tsx`
  - `apps/web/src/routes/reading-notes.tsx`
  - `apps/web/src/routes/reading-topics.tsx`
  - `doc/决策记录.md`（新增红线条目）
- 拍板要点：
  - 选 B：新建独立的 `ProtectedShell` 组件，集中拉用户态。
  - 路由层（具体而言是 `ProtectedShell`）负责拿用户态；`AppShell` 只做纯展示壳。
  - 不在根路由做全局拉取，也不在 Provider 里做隐式查询。
  - 公开页（登录页等）不复用完整 `AppShell`；`AppShell` 保留为"应用内壳"，公开页继续走简化壳或独立布局。
  - 这样 `authViewModel` 不需要承担"未登录但仍展示完整业务侧栏"的奇怪场景。
  - 存量迁移：只剥离数据获取，不重写布局。
    - 保留 `AppShell` / `AppSidebar` 的 UI 结构。
    - 把 `useCurrentUser` / `useAuthInit` 等查询上提到 `ProtectedShell`。
    - `AppSidebar` 改为只吃 props。
  - `AppSidebar` 输入契约（终态）：
    - `activeKey`
    - `searchValue`
    - `onSearchChange`
    - `stats`
    - `authViewModel`（建议显式化，包含 `loggedIn` / `initial` / `displayName` 或 `userLabel` / `canOpenSettings`）
    - `quickLinks`
  - `authViewModel` 显式化：侧栏不再自己查询认证状态。
- 建议动作：
  - 新建 `apps/web/src/components/protected-shell.tsx`，集中调用 `useCurrentUser` / `useAuthInit` 等查询。
  - `AppShell` / `AppSidebar` 改为纯展示组件，按上面输入契约接收 props。
  - 设置页改走 `ProtectedShell` → `AppShell` 链路，移除直接拼接 `AppSidebar` 的写法。
  - 同步更新 [决策记录.md](doc/决策记录.md) 新增 WL-005 相关红线条目。
- 验收标准：
  - 主要后台页面使用一致的壳层模式。
  - `AppSidebar` 的职责更单一，重复认证查询减少。
  - 页面视觉与行为无回归。
  - `pnpm typecheck` 与 `pnpm lint` 通过。

## WL-006 拆分前端超大文件，先从设置页和书籍详情开始

- 优先级：P3
- 类型：结构规整 / 维护成本
- 背景：
  - `bookshelf.tsx`、`settings.tsx`、`book-detail-sheet.tsx` 体量已经过大。
  - 当前还能维护，但继续叠加 M2/M3 能力会明显增大改动风险。
- 目标：
  - 在不改业务行为的前提下，把大文件拆成更稳定的模块。
  - 为后续 M2 阅读留痕和 M3 AI 能力接入预留清晰位置。
- 涉及文件：
  - `apps/web/src/routes/settings.tsx`
  - `apps/web/src/components/book-detail-sheet.tsx`
  - `apps/web/src/routes/bookshelf.tsx`（第二阶段）
  - 新建目录：
    - `apps/web/src/routes/settings-tabs/`（按 Tab 拆）
    - `apps/web/src/components/book-detail-sheet/`（子组件目录）
  - `doc/决策记录.md`（无需新增，红线已在 WL-005 中处理）
- 拍板要点：
  - 拆分粒度：
    - 设置页按"一个 Tab 一个文件"拆，不再按"超过多少行才拆"。Tab 本身就是天然边界。
    - `book-detail-sheet` 不拆成 4 个散文件直接平铺，而是建 `book-detail-sheet/` 文件夹，里面拆 4 个子组件 + 一个外层协调入口。
  - 文件结构：
    - `book-detail-sheet/BookArchiveTab.tsx`
    - `book-detail-sheet/BookCoverPanel.tsx`
    - `book-detail-sheet/BookFilesPanel.tsx`
    - `book-detail-sheet/BookPlaceholderTabs.tsx`
    - `book-detail-sheet/index.tsx`（外层协调入口）
  - 状态归属原则（写死）：
    - 局部状态尽量留在所属子组件。
    - 跨区块共享状态才上提到父组件。
    - 不为减少 prop drilling 而提前引入全局状态。
    - 禁止子组件之间横向读取彼此状态，统一经父组件传递。
  - 外层 `book-detail-sheet.tsx` 保留的状态（明确清单）：
    - 当前书籍数据（`book.data`、`files.data`、`covers.data` 等）
    - 全局提示消息（成功 / 失败提示）
    - 编辑模式开关（`editMode`）
    - 当前正在编辑的字段（`editingField`、`editValue`、`editTagIds`）
    - 元数据抓取弹窗状态（`showMetadataDialog`、`metadataResult`、`selectedFields`、`fetchCoverChecked`）
    - 详情级别的激活 Tab（`activeTab`）
    - 当前书籍 ID / 抽屉开关（`bookId`、`open`、`onClose`）
  - 适合下放到子组件的状态示例：
    - 文件区自己的"某个操作菜单是否展开"
    - 封面区自己的"本地上传 input 是否清空"
    - 占位区里的纯展示文案
    - 某个局部 hover / 展开样式状态
  - `BookPlaceholderTabs` 拆分方式：按当前 UI 1:1 拆，但 props 命名按终态语义预留。
  - 统一加 `index.ts`：新拆目录（`book-detail-sheet/`、`settings-tabs/` 等）都统一加 `index.ts` 统一导出。
- 建议动作：
  - 第一阶段：拆设置页各 Tab、建 `settings-tabs/` 目录、统一加 `index.ts`。
  - 第一阶段：建 `book-detail-sheet/` 目录，按上面 4 个子组件拆 + 外层协调入口。
  - 第二阶段：拆书架卡片视图与导入弹窗（本次不实施，留待后续）。
  - 拆分时保持 props 边界清晰，遵守"跨区共享状态留外层"原则。
  - 不在拆分过程中顺手改业务行为；只做结构调整。
- 验收标准：
  - 页面行为不变。
  - 单文件体量明显下降。
  - 新结构能让后续功能更容易定位落点。
  - `pnpm typecheck` 与 `pnpm lint` 通过。
