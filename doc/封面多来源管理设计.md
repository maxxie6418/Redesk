## 1. 背景

当前系统已实现：
- `book_covers` 表支持多封面存储（`source_type` 区分来源，`is_active` 标记当前封面）
- EPUB 上传时自动抽取封面（`source_type = EPUB_EXTRACTED`）
- 详情页封面管理 UI（列表、激活、删除）
- 从介绍页抓取封面（`POST /books/:id/covers/fetch`）
- 元数据预填（`POST /books/metadata/fetch`，豆瓣/NeoDB HTML 解析）

缺失功能：
- 用户上传本地封面
- 详情页元数据选择性更新弹窗
- 批量封面抓取
- CSV 导入时自动下载封面
- 添加书籍时连带下载封面图

## 2. 设计决策

| 决策 | 结论 | 依据 |
| --- | --- | --- |
| 封面来源分类 | 三套：EPUB 抽取 / 介绍页抓取 / 用户上传 | 用户需要区分封面来源并手动选择 |
| 封面激活策略 | 所有新增封面均不自动激活 | 用户确认：用户应手动选择使用哪一套 |
| 元数据更新策略 | 选择性应用弹窗，用户勾选要更新的字段 | 比自动填空更灵活可控 |
| 批量封面抓取 | 仅添加新记录，不替换当前封面 | 与单品封面策略一致 |
| CSV 导入封面 | 有 `cover_url` 时自动下载为介绍页抓取封面 | 减少用户后续手动操作 |
| 实现方式 | 方案一：增量补充，不重构现有代码 | 改动最小，风险最低 |

## 3. 数据模型变更

不需要新增数据库表或字段。现有 `book_covers` 表完全可复用：

| source_type | 说明 | 状态 |
| --- | --- | --- |
| EPUB_EXTRACTED | EPUB 文件上传时自动抽取 | 已有 |
| REMOTE_FETCHED | 从介绍页（豆瓣/NeoDB）抓取下载 | 已有 |
| USER_UPLOADED | 用户手动上传的本地图片 | **新增** |

`source_label` 字段复用：
- `USER_UPLOADED` → `'upload'`
- `REMOTE_FETCHED` → `'douban'` / `'neodb'`（已有）

## 4. 后端 API 变更

### 4.1 用户上传封面

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/books/:id/covers/upload` | 上传本地图片作为封面 |

请求：`multipart/form-data`
- `file`：图片文件（jpg/png/webp/gif/bmp，上限 5MB）
- `source_label`：可选，默认 `'upload'`

后端处理：
1. 校验文件为图片格式，大小 ≤ 5MB
2. 存储 `storage/covers/{bookId}/upload_{timestamp}_{random}{ext}`
3. `upsertBookCover` 入库，`source_type = 'USER_UPLOADED'`，`activate = false`
4. 返回封面记录

响应 201：`{ "data": { /* cover 对象 */ } }`

### 4.2 批量抓取封面

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/books/batch/fetch-covers` | 批量从介绍页抓取封面 |

请求：
```json
{ "ids": [1, 2, 3, 5] }
```

后端处理：
1. 遍历指定书籍，筛选有 `source_url` 的
2. 逐本调用 `fetchBookMetadataFromUrl` + `downloadRemoteCover`
3. 抓取到的封面 `activate = false`
4. 返回每本书的抓取结果

响应 200：
```json
{
  "data": {
    "total": 4,
    "fetched": 2,
    "skipped": 1,
    "failed": 1,
    "results": [
      { "book_id": 1, "status": "fetched", "cover_id": 15 },
      { "book_id": 2, "status": "skipped", "reason": "缺少 source_url" },
      { "book_id": 3, "status": "fetched", "cover_id": 16 },
      { "book_id": 5, "status": "failed", "reason": "抓取超时" }
    ]
  }
}
```

### 4.3 元数据选择性应用

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/books/:id/metadata/apply` | 选择性应用抓取到的元数据字段 |

请求：
```json
{
  "fields": {
    "description": "从介绍页抓取的简介",
    "publisher": "商务印书馆",
    "isbn": "9787100040945"
  },
  "fetch_cover": true
}
```

后端处理：
1. 仅更新 `fields` 中指定的字段（不覆盖未列出的字段）
2. `fetch_cover = true` 时同时下载封面作为新记录（`activate = false`）
3. 返回更新后的书籍对象

响应 200：`{ "data": { /* book 对象 */ } }`

### 4.4 CSV 导入自动下载封面

修改现有 `POST /books/import` 流程：
- 导入时如果行中有 `cover_url`，自动调用 `downloadRemoteCover` 下载封面图
- `source_type = 'REMOTE_FETCHED'`，`activate = false`
- 仅当该书首次导入且无其他封面时才激活

### 4.5 添加书籍时连带下载封面

修改现有 `POST /books` 流程：
- 创建书籍时如果请求中包含 `cover_url`，后端自动下载封面
- `source_type = 'REMOTE_FETCHED'`，`activate = false`

## 5. 前端交互变更

### 5.1 详情页封面管理区改造

当前 `book-detail.tsx` 的封面管理区改造内容：

1. **新增"上传封面"按钮**：点击弹出文件选择器，上传后作为 `USER_UPLOADED` 类型封面记录添加，不自动激活
2. **"手动下载封面"按钮保留**：继续从 `source_url` 抓取，作为 `REMOTE_FETCHED` 类型记录添加
3. **封面列表分组展示**：按来源分组（EPUB 抽取 / 介绍页抓取 / 用户上传），每组内列出具体封面缩略图、来源标签、激活状态、激活/删除按钮

### 5.2 详情页元数据更新弹窗

新增"从介绍页抓取更新"按钮：

1. 点击后调用 `POST /books/metadata/fetch`（传入 `source_url`）
2. 弹窗展示抓取结果与当前值的对比：
   - 每行一个字段，左侧勾选框，右侧展示"抓取值"和"当前值"
   - 当前值与抓取值相同的字段默认不勾选
   - 当前为空的字段默认勾选
   - 封面作为独立勾选项，勾选后下载为新封面记录
3. 点击"确认应用"调用 `POST /books/:id/metadata/apply`

### 5.3 书架页批量操作

当前 `bookshelf.tsx` 的批量操作菜单新增 `fetch_covers` 操作：

- 操作名称："抓取介绍页封面"
- 仅对选中且有 `source_url` 的书籍执行
- 调用 `POST /books/batch/fetch-covers`
- 完成后弹出结果摘要（成功 N 本、跳过 M 本、失败 K 本）

### 5.4 添加书籍时的封面处理

当前创建书籍流程已有"从链接获取信息"功能，改动：
- 抓取结果中的 `cover_url` 继续展示
- 创建书籍提交时，后端收到 `cover_url` 参数后自动下载封面存为新记录（`activate = false`）
