01 一句话定位与三层结构

Redesk 是自托管的个人阅读管理与 AI 陪读系统。藏书 — 阅读 — 沉淀 — 思考 的数据闭环；数据存本地 SQLite，自托管 Docker 部署，AI 作为增强层分阶段引入。

基础层 · S1

书架管理

书籍元数据、文件、分类、标签、状态、回收站、文件管理（多文件 / 主阅读文件 / 三态存储 / 封面抽取）、导出与备份、OPDS 1.2、概览首页、设置页。

M0 · M1 已闭环

沉淀层 · S2

阅读与笔记

epub.js 在线阅读、CFI 进度保存 / 恢复、高亮 / 划线 / 波浪线、附注、独立笔记、书签、跳回原文、笔记 / 高亮 FTS5 全文搜索、阅读笔记汇总页、笔记 / 高亮 / 标记导出。

M2 已全线闭环

增强层 · S3 / P2

主题阅读 + AI

主题（话题）已超前落地，AI 阶段一（管理 / 阅读辅助）+ RAG（书库级问答）以及对象存储云同步、阅读器与统计增强均待定位。AI 内容存 ai_assets 独立表，与用户内容隔离展示。

M3 已超前实现 · M4 / M5 待定位

阶段开发不得反向改变该层次（决策记录 · 产品层次，2026-06-27）。

04 数据库结构（23 张业务表）

表命名以复数为主；时间戳统一 ISO 8601 UTC；主键统一 id INTEGER PRIMARY KEY（自增 rowid）；业务实体表带 owner_id，从属表通过父表继承归属。当前部署实例：23 张业务表 + 3 套 FTS5 虚表 + 33 条迁移记录。

05 已确定（决策）的红线与约定

以下内容已在《决策记录》中以"已确认决策"或"建模决策"形式锁定，实现时不得违反。

5.1 建模决策（数据模型 §1）

一书一分类 books.category_id 单意外键，不建多对多关联表。分类是"这本书对个人的主要用途 / 立场"。
分类用户自定义 不内置通用类型树；当前平级使用，parent_id 留可选层级不强制。
存档 是独立状态，不是删除 STORED 与软删除 deleted_at 是完全不同的两条路径。不得把"存档"实现为归档 / 删除。
软删除统一字段 deleted_at TEXT NULL 标记，非物理删除。回收站恢复需求。
阅读痕迹归属原书 高亮 / 笔记 book_id 直接归属原书；主题仅"引用"。
主题软删除与软引用 topics.deleted_at 软删除；引用表 ON DELETE CASCADE 到原痕（高亮 / 笔记），原痕物理删除时引用自动摘除。
AI 派生资产隔离 ai_assets 独立表，不与用户笔记 / 高亮混表；展示层亦区分。
弹性字段 books.custom_attributes JSON 列承载自定义收藏属性。
owner_id 预留多用户 根实体直接带 owner_id；从属表通过父表校验；无父实体的暂存资源自带 owner_id。当前单账户下恒为同一值。
进度独立表 reading_progress 独立于 books，按 (book_id, owner_id)，与书籍元数据解耦。
笔记双格式存储 content_html + content_markdown 双存。编辑用 HTML（TipTap），导出用 Markdown。

5.2 AGENTS.md 技术红线（不得擅改）

  1. 存档是独立状态，不是删除：状态枚举 STORED，与软删除 deleted_at 是完全不同的两条路径。
  2. 主题只引用不占有阅读痕迹：高亮 / 笔记 book_id 归属原书；主题用 ON DELETE CASCADE 软引用，删主题不动原始数据，原痕删除时引用自动摘除。
  3. AI 内容与用户内容隔离：AI 生成内容存 ai_assets 独立表，展示层亦区分，绝不与用户笔记 / 高亮混表。
  4. 不默认强依赖云端：云同步为可选增强；只同步文件层 + 备份副本，不同步在线数据库。优先支持内置 S3 / OSS；rclone / Google Drive / Dropbox 作为后置可选同步方案。
  5. 数据主权：导出必须用通用格式（Markdown / JSON / CSV），不依赖 Redesk 专有结构。
  6. 一书一分类：books.category_id 单意外键；不建多对多关联表。
  7. owner_id 预留多用户：用户拥有的根实体表带 owner_id；从属表通过父表继承归属，查询与写入必须校验 owner 边界。
