# Redesk 用户权限与身份体系设计

## 一、总体设计原则

1. **层级递进**：权限从低到高为「未登录 → 浏览 → 阅读 → 使用 → 管理员」，高级别包含低级别所有能力。
2. **书籍可见性独立于权限**：书籍有 `PUBLIC` / `PRIVATE` 两种可见性，决定了其他用户能否看到这本书的元数据和文件。
3. **高亮与笔记可见性分离**：
   - **高亮（原文划线）**：依附于书籍的客观标记，跟随书籍 `visibility`——公开书的高亮所有人可见，私有书的高亮仅 owner 可见。
   - **笔记（用户文字）**：用户的私密思考，永远按 `owner_id` 隔离，仅本人可见（管理员除外）。
4. **权限与内容归属解耦**：权限决定「能做什么操作」，`owner_id` 决定「能看到谁的数据」，两者互不替代。
5. **管理员不受限**：管理员（`is_admin = 1`）默认拥有全部权限，不受权限级别约束，可查看所有用户的所有数据。

---

## 二、权限层级定义

### 层级总览

| 层级 | 标识 | 定位 | 一句话概括 |
|------|------|------|-----------|
| 未登录（匿名） | — | 访客 | 看看有什么书 |
| 浏览 | `view` | 观察者 | 看有什么书 + 别人怎么标记的 |
| 阅读 | `read` | 读者 | 自己读书 + 构建自己的阅读痕迹 |
| 使用 | `use` | 贡献者 | 上传书籍 + 为他人提供阅读内容 |
| 管理员 | `admin` | 运维 | 管系统 + 管用户 |

---

### 2.1 未登录（匿名）

**认证状态**：未登录 / 无会话

**核心定位**：访客，只能看到书架，知道收藏了哪些书

| 模块 | 能力 | 说明 |
|------|------|------|
| 书架 | 查看公开书籍列表 | 封面 + 书名 + 作者，支持网格/卡片等视图 |
| 搜索 | 搜索公开书籍 | 仅列表级搜索，不能点进详情 |
| 认证 | 登录 / 注册入口 | 显示登录按钮 |

**不可访问**：
- 书籍详情页
- 高亮、笔记、主题、分类详情
- 阅读器 / 文件下载
- 任何写操作接口
- 个人设置

---

### 2.2 浏览（view）

**认证状态**：已登录，`permission_level = 'view'`

**核心定位**：观察者，可以看到书籍的具体信息，获知到其他用户的阅读标记（高亮），但不能看别人的笔记文字

| 模块 | 能力 | 说明 |
|------|------|------|
| 书架 | 查看所有可见书籍 | 自己的全部书 + 他人公开的书 |
| 书籍详情 | 查看完整元数据 | ISBN、出版社、简介、评分、状态等 |
| **高亮（原文划线）** | 查看公开书籍上的高亮 | 所有人对公开书的划线都可见，私有书仅看自己的 |
| **笔记（用户文字）** | 仅看自己的笔记 | 笔记永远私密，他人不可见 |
| 主题 | 仅看自己的主题 | 按 `owner_id` 隔离 |
| 分类 / 标签 | 查看自己的分类与标签 | 只读，按 `owner_id` 隔离 |
| 阅读状态 | 查看书籍阅读状态 | 收藏 / 在读 / 已读 / 存档 |

**不可访问 / 不可操作**：
- 阅读器（书籍文件不可访问）
- 文件信息（格式、大小、下载按钮全部隐藏）
- 任何上传、编辑、删除操作
- 写高亮 / 写笔记 / 写书签
- 记录阅读进度
- 导出数据
- 云连接配置
- 个人设置

---

### 2.3 阅读（read）

**认证状态**：已登录，`permission_level = 'read'`

**核心定位**：读者，可以获得阅读权限，基于已有书籍构建自己的阅读经历

> 关键设定：拥有阅读权限即拥有独立的留痕能力——阅读进度、高亮、笔记、书签、主题都是用户自己的，与书籍的上传者无关。

| 模块 | 能力 | 说明 |
|------|------|------|
| 浏览的全部能力 | — | 继承浏览级别所有能力 |
| 阅读器 | 打开并阅读书籍 | 访问书籍文件（EPUB / PDF 等），仅限可见的书籍 |
| 阅读进度 | 自动记录阅读位置 | 下次打开自动跳转，独立保存，仅自己的 |
| **高亮（原文划线）** | 完整的增删改查 | 可在公开书上写高亮，自己的高亮仅自己可删改 |
| **笔记（用户文字）** | 完整的增删改查 | 仅自己可见，他人不可见 |
| 书签 | 完整的增删改查 | 仅自己的 |
| 主题 | 完整的增删改查 | 用户自己的主题体系 |
| 分类 / 标签 | 完整的增删改查 | 用户自己的分类与标签 |

**不可操作**：
- 上传新书籍 / 新文件
- 编辑书籍元数据（书名、作者、ISBN、封面等）
- 修改书籍可见性（PUBLIC / PRIVATE）
- 替换 / 删除书籍文件
- 删除书籍
- 导出数据
- 云连接配置
- 个人设置

---

### 2.4 使用（use）

**认证状态**：已登录，`permission_level = 'use'`

**核心定位**：贡献者，可以为他人提供阅读素材，与管理员差异在于不能控制环境和设置

| 模块 | 能力 | 说明 |
|------|------|------|
| 阅读的全部能力 | — | 继承阅读级别所有能力 |
| 书籍上传 | 上传新书、导入书籍 | 单本上传 / 批量导入 / 元数据抓取 |
| 书籍编辑 | 修改书籍元数据 | 书名、作者、ISBN、封面、分类、标签等 |
| 书籍管理 | 删除 / 存档 / 修改可见性 | 管理自己的书籍 |
| 文件管理 | 替换文件、多封面管理 | 管理自己的文件资源 |
| 导出 | 导出书籍元数据 / 笔记 / 高亮 | Markdown / JSON / CSV |
| 个人设置 | 阅读器配置、个人偏好 | 仅影响自己 |
| 云连接 | 配置自己的存储连接 | S3 / OSS 等 |

**不可操作（系统核心）**：
- 用户管理（创建 / 删除 / 权限变更）
- 系统级备份与恢复
- 全局系统配置

---

### 2.5 管理员（admin）

**认证状态**：已登录，`is_admin = 1`

**核心定位**：运维，管系统 + 管用户

- 拥有「使用」级别的全部能力
- 用户管理：创建、删除、启用/禁用、重置密码、修改权限级别
- 系统备份与恢复
- 全局系统配置
- 查看所有用户的所有数据（包括所有人的笔记）

---

## 三、数据可见性规则

### 3.1 书籍可见性

书籍的 `visibility` 字段（`PUBLIC` / `PRIVATE`）决定了非 owner 用户能否看到这本书。

| 场景 | 未登录 | 浏览 | 阅读 | 使用 | 管理员 |
|------|--------|------|------|------|--------|
| 自己的书（无论 PUBLIC / PRIVATE） | ❌ | ✅ | ✅ | ✅ | ✅ |
| 他人的书（PUBLIC） | 列表可见 ✅ | 详情可见 ✅ | 可阅读 ✅ | 可阅读 + 留痕 ✅ | ✅ |
| 他人的书（PRIVATE） | ❌ | ❌ | ❌ | ❌ | ✅ |

> **注意**：未登录用户仅能看到公开书籍的列表（封面+书名+作者），不能进入详情页。

---

### 3.2 高亮（原文划线）可见性

**核心原则**：高亮跟随书籍 `visibility`，公开书的高亮所有人可见，私有书的高亮仅 owner 可见。

> 高亮本质是对书籍原文的标记，属于书籍的附属信息，不是用户的私密创作。

| 场景 | 未登录 | 浏览 | 阅读 | 使用 | 管理员 |
|------|--------|------|------|------|--------|
| 公开书上的高亮（所有用户） | ❌ | ✅ 可看 | ✅ 可看 | ✅ 可看+写 | ✅ 全量 |
| 私有书上的高亮（仅 owner） | ❌ | 仅自己的 ✅ | 仅自己的 ✅ | 仅自己的 ✅ | ✅ 全量 |
| 自己的高亮（增删改） | ❌ | ❌ 不能写 | ✅ 可写 | ✅ 可写 | ✅ |

---

### 3.3 笔记（用户文字）可见性

**核心原则**：笔记永远按 `owner_id` 隔离，仅本人可见（管理员除外）。

> 笔记是用户的私密思考和表达，即使写在公开书上，他人也不可见。

| 场景 | 未登录 | 浏览 | 阅读 | 使用 | 管理员 |
|------|--------|------|------|------|--------|
| 自己的笔记 | ❌ | ❌ 不能看 | ✅ 可看+写 | ✅ 可看+写 | ✅ |
| 他人的笔记 | ❌ | ❌ 不可见 | ❌ 不可见 | ❌ 不可见 | ✅（管理员） |

---

### 3.4 高亮与笔记的语义区分

| 内容类型 | 数据归属 | 本质 | 存储位置 | 可见性规则 |
|----------|----------|------|----------|-----------|
| **高亮 content** | 书籍原文 | 用户标记的段落，自动提取 | `highlights.content` | 跟随书籍 `visibility` |
| **高亮 mark_type** | 用户选择 | IMPORTANT / QUESTION / INSIGHT 等标签 | `highlights.mark_type` | 跟随书籍 `visibility` |
| **笔记 content** | 用户创作 | 用户自己写的思考和表达 | `notes.content` | 永远按 `owner_id` 隔离 |

**实现层面**：
- 不需要给高亮或笔记额外添加 `visibility` 字段
- 高亮查询时，根据书籍的 `visibility` 和用户的权限级别动态过滤
- 笔记查询时，始终按 `owner_id` 过滤（管理员除外）

---

### 3.5 文件访问

- 仅 `read` 及以上权限可以访问书籍文件（打开阅读器、下载）
- `view` 及以下权限完全看不到文件相关信息（格式、大小、下载按钮全部隐藏）

---

### 3.6 其他数据可见性

| 数据类型 | 可见性规则 |
|----------|-----------|
| 阅读进度 | 按 `owner_id` 隔离，仅自己可见 |
| 书签 | 按 `owner_id` 隔离，仅自己可见 |
| 主题 | 按 `owner_id` 隔离，仅自己可见 |
| 分类 / 标签 | 按 `owner_id` 隔离，仅自己可见 |
| 云连接配置 | 按 `owner_id` 隔离，仅自己可见 |

---

## 四、权限校验实现原则

### 4.1 后端校验（强制）

所有权限校验在后端完成，前端隐藏按钮仅为体验优化。

### 4.2 统一校验函数

在 `auth.ts` 中封装统一的权限检查：

- `requirePermission(req, minLevel)` — 要求用户至少拥有指定级别的权限
- `requireAdmin(req)` — 要求管理员权限（已存在）
- `requireUserId(req)` — 要求已登录（已存在，最低等同于 view 级）

### 4.3 数据边界校验

权限校验不能替代数据归属校验：

- 写操作必须校验 `owner_id` 匹配（或书籍 `visibility` 允许他人写入留痕）
- 读操作必须根据数据类型选择合适的过滤策略：
  - 书籍：`owner_id` 匹配 或 `visibility = 'PUBLIC'`
  - 高亮：书籍 `visibility = 'PUBLIC'` 则所有人可见，否则仅 `owner_id` 匹配
  - 笔记：始终仅 `owner_id` 匹配
- 管理员不受上述限制

---

## 五、书籍默认可见性

- 新建 / 导入书籍时，`visibility` 默认为 `PUBLIC`
- 用户可手动修改为 `PRIVATE`
- 存量数据保持原有 `visibility` 值不变

---

## 六、与现有字段的映射

| 现有字段 | 含义 | 在新体系中的角色 |
|----------|------|-----------------|
| `is_admin` | 是否管理员 | 最高权限级别，不受 `permission_level` 约束，可查看所有数据 |
| `is_active` | 账户是否启用 | 禁用后无法登录，不影响权限层级 |
| `visibility`（书籍） | 书籍可见性 | 决定非 owner 能否看到该书，同时影响该书上高亮的可见性 |
| `owner_id` | 数据归属 | 数据隔离的核心机制，笔记等私密数据严格按此隔离 |

---

## 七、数据库变更

新增字段（用户表）：

```
users.permission_level  TEXT  NOT NULL  DEFAULT 'use'
```

取值：`'view' | 'read' | 'use'`

默认值 `'use'` 保证存量用户不受影响。

**不需要额外变更**：
- 高亮和笔记不需要新增 `visibility` 字段
- 可见性逻辑通过查询时动态过滤实现

---

## 八、前端交互要点

1. 未登录用户访问需要登录的页面 → 跳转登录页
2. 权限不足时，前端隐藏对应按钮 / 入口
3. 若用户直接访问受限页面 → 展示无权限提示
4. 用户管理界面提供权限级别下拉选择（浏览 / 阅读 / 使用）
5. 浏览权限用户的 UI 中：
   - 不出现「下载」「打开阅读器」「文件格式」等与文件相关的元素
   - 公开书籍详情页可展示「其他人标记的高亮」，但不能展示笔记内容
6. 阅读及以上权限用户的 UI 中：
   - 高亮列表区分「我的高亮」和「其他人标记的高亮」
   - 笔记列表始终只展示自己的笔记

---

## 九、核心设计决策总结

| 决策 | 内容 |
|------|------|
| 高亮 vs 笔记 | 高亮是原文标记（公开），笔记是用户文字（私密） |
| 高亮可见性 | 跟随书籍 `visibility`，公开书的高亮所有人可见 |
| 笔记可见性 | 永远按 `owner_id` 隔离，他人不可见（管理员除外） |
| 阅读权限留痕 | 阅读权限用户拥有独立留痕能力，可在公开书上创建自己的高亮/笔记 |
| 书籍默认公开 | 新书默认 `PUBLIC`，为他人提供阅读素材 |
