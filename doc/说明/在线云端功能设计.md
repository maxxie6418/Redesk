> 本文档记录 Redesk 在线云端功能的完整设计。核心思路是将云端连接配置抽象为独立的配置条目，由"存储"页面管理连接配置与数据路由，由"云备份"页面管理发送与接收动作。两者共享同一套云连接配置，职责解耦。

## 第一部分：云连接配置

### 1.1 设计目标

将所有云端存储的连接配置从 `settings` 表的平铺键值对重构为独立的配置条目，支持多种云端类型和多个实例。

核心目标：

1. 每个云端连接是一个完整的配置条目，包含类型、连接参数、状态等，不再依赖平铺键值对。
2. 支持多种云端类型：S3 兼容对象存储（OSS / R2 / MinIO / B2）、WebDAV，后续可扩展。
3. 最多保存 5 个连接配置条目。
4. 每个条目可独立测试连接、启用/禁用。
5. 敏感信息（密钥、密码）在 API 返回时脱敏，在日志和错误响应中不得输出明文。

### 1.2 已确认决策

以下决策来源于《决策记录》：

- **2026-06-27 / 云同步方案**：云同步优先采用应用内置 S3 兼容对象存储同步（阿里云 OSS / AWS S3 / Cloudflare R2 / MinIO / B2），用户在设置页填写 endpoint/bucket/key/secret 即可；只同步书籍文件与 SQLite 备份副本，不同步在线数据库。rclone / Google Drive / Dropbox 后置为可选项。
- **2026-06-27 / 不默认强依赖云端**：云同步仍为可选增强；只同步文件层 + 备份副本，不同步在线数据库。优先支持内置 S3/OSS；rclone / Google Drive / Dropbox 作为后置可选同步方案。
- **2026-07-10 / 云连接配置条目化**（新增）：云端连接配置从 `settings` 表平铺键值对重构为独立的 `cloud_connections` 表条目，支持多类型、多实例、多用途分配。

### 1.3 数据模型

#### 1.3.1 `cloud_connections` 云连接配置表

```sql
CREATE TABLE cloud_connections (
  id            INTEGER PRIMARY KEY AUTOINCREMENT,
  owner_id      INTEGER NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  name          TEXT    NOT NULL,
  type          TEXT    NOT NULL,                -- 's3' / 'webdav'
  config        TEXT    NOT NULL DEFAULT '{}',   -- JSON，类型相关的连接参数
  is_active     TEXT    NOT NULL DEFAULT 'true', -- 是否启用
  tested_at     TEXT,                            -- 最后一次测试通过时间
  created_at    TEXT    NOT NULL DEFAULT (strftime('%Y-%m-%dT%H:%M:%SZ','now')),
  updated_at    TEXT    NOT NULL DEFAULT (strftime('%Y-%m-%dT%H:%M:%SZ','now'))
);
```

约束：

- 同一 owner 最多 5 条记录。
- `type` 决定 `config` 的 JSON 结构。

#### 1.3.2 `config` JSON 结构定义

**S3 类型**（`type = 's3'`）：

```json
{
  "provider": "r2",
  "endpoint": "https://xxx.r2.cloudflarestorage.com",
  "bucket": "redesk-files",
  "region": "auto",
  "access_key": "AKID...",
  "secret_key": "Secret...",
  "public_url": "https://cdn.example.com",
  "prefix": "files/"
}
```

**WebDAV 类型**（`type = 'webdav'`）：

```json
{
  "url": "https://dav.example.com",
  "username": "user",
  "password": "token...",
  "base_path": "/redesk/"
}
```

字段说明：

| 字段 | S3 | WebDAV | 说明 |
| --- | --- | --- | --- |
| `provider` | ✅ | — | Provider 标识：r2 / s3 / minio / aliyun |
| `endpoint` | ✅ | — | S3 Endpoint URL |
| `bucket` | ✅ | — | Bucket 名称 |
| `region` | ✅ | — | Region，默认 'auto' |
| `access_key` | ✅ | — | Access Key ID |
| `secret_key` | ✅ | — | Secret Access Key |
| `public_url` | ✅ | — | 公开访问 URL（可选） |
| `prefix` | ✅ | — | 对象 key 前缀（可选），用于隔离命名空间 |
| `url` | — | ✅ | WebDAV 服务器 URL |
| `username` | — | ✅ | 用户名 |
| `password` | — | ✅ | 密码或 token |
| `base_path` | — | ✅ | 远端基础路径（可选） |

#### 1.3.3 `cloud_usage_assignments` 用途分配表

```sql
CREATE TABLE cloud_usage_assignments (
  id              INTEGER PRIMARY KEY AUTOINCREMENT,
  owner_id        INTEGER NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  usage           TEXT    NOT NULL,  -- 用途标识，见下方枚举
  connection_id   INTEGER NOT NULL REFERENCES cloud_connections(id) ON DELETE CASCADE,
  priority        INTEGER NOT NULL DEFAULT 0,  -- 同一用途多目标时的优先级，数值越小优先级越高
  created_at      TEXT    NOT NULL DEFAULT (strftime('%Y-%m-%dT%H:%M:%SZ','now'))
);
```

用途枚举：

| 用途 | 说明 | 涉及数据 |
| --- | --- | --- |
| `book_files` | 书籍文件存储 | 书籍文件本体（EPUB / PDF / MOBI 等） |
| `covers` | 封面图片存储 | 书籍封面图片 |
| `notes` | 笔记同步存储 | 笔记数据（HTML / Markdown） |
| `backup_db` | 数据库备份 | SQLite 数据库备份副本 |
| `backup_full` | 完整备份 | 包含数据库 + 文件索引 + 文件本体的完整备份包 |

约束：

- 同一 `usage` 可以关联多个 `connection_id`（多目标冗余存储）。
- 同一 `usage` + `connection_id` 不重复。
- `priority` 用于决定读取时的优先顺序和写入时的目标顺序。

### 1.4 配置迁移

从当前 `settings` 表平铺键值对迁移到新表：

迁移规则：

| settings 键 | 迁移目标 |
| --- | --- |
| `oss_provider` / `oss_endpoint` / `oss_bucket` / `oss_access_key` / `oss_secret_key` / `oss_region` / `oss_public_url` | → `cloud_connections` 一条 `type = 's3'` 记录 |
| `default_storage_mode` | → `settings` 表保留（与连接配置无关） |
| `storage_driver` | → 删除（不再需要） |

如果 `settings` 表中已有完整的 S3 配置（endpoint + bucket + access_key + secret_key 都非空），迁移时自动创建一条 `cloud_connections` 记录，并为 `book_files` 和 `covers` 创建对应的用途分配。

### 1.5 已知问题与本次修复

当前 `settings` 表平铺键值对方案存在以下已知问题，本次重构一并修复：

1. **部分写入导致配置丢失**：`handleSave` 中 `endpoint || null` 在 endpoint 为空字符串时发送 `null`，后端 `isPresent(null)` 返回 `false`，执行 `writeSetting(key, null)` 删除该行。而 `access_key || undefined` 在空值时保留旧值。导致保存后只剩 access_key 和 secret_key，其他字段被删除。
2. **配置与使用场景耦合**：所有云端操作共用同一套配置，无法为不同数据类型指定不同云端目标。
3. **只能配一套云端**：无法同时使用 OSS 存文件 + WebDAV 存笔记。
4. **"发送到云端"功能位置不当**：当前在书籍管理页面，应归属云备份操作。

重构后，配置以完整条目存储，不存在部分写入问题；用途分配表支持多目标；连接配置表支持多类型多实例。

## 第二部分：存储配置（存储页面职责）

### 2.1 设计目标

存储页面负责管理**数据路由配置**——即每种数据类型应该存往哪个云端连接。

核心目标：

1. 管理云连接配置条目（创建、编辑、删除、测试连接）。
2. 管理用途分配（哪种数据存往哪个连接）。
3. 管理默认存储模式（local_only / cloud_only / dual）。
4. 展示本地存储概况。
5. 展示各云端连接的状态和用量。

### 2.2 存储页面结构

存储 Tab 的内容重新组织为以下区块：

```
存储页面
├── 本地存储概况（已有，保留）
│   ├── 总占用、书籍文件、封面图片、数据库大小
│   └── 缓存清理
├── 默认存储方式（已有，保留）
│   └── local_only / cloud_only / dual 三态选择
├── 云连接配置（新增，替代原有 CloudStorageCard）
│   ├── 连接列表（最多 5 条）
│   │   ├── 条目卡片：名称、类型标识、连接状态、最后测试时间
│   │   ├── 操作：编辑、测试连接、启用/禁用、删除
│   │   └── 新增连接按钮
│   └── 新建/编辑连接弹窗
│       ├── 类型选择：S3 兼容 / WebDAV
│       ├── 名称输入
│       ├── 类型相关配置表单（S3: endpoint/bucket/key/secret/...；WebDAV: url/username/password/...）
│       └── 测试连接按钮
└── 数据路由配置（新增）
    ├── 书籍文件 → 选择连接（单选，从已启用的连接中选择）
    ├── 封面图片 → 选择连接（单选）
    ├── 笔记同步 → 选择连接（单选）
    ├── 数据库备份 → 选择连接（可多选，支持冗余）
    └── 完整备份 → 选择连接（可多选，支持冗余）
```

### 2.3 API 设计

#### 云连接配置 CRUD

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | /cloud-connections | 列出所有连接（密钥脱敏） |
| POST | /cloud-connections | 创建连接 |
| PATCH | /cloud-connections/:id | 更新连接 |
| DELETE | /cloud-connections/:id | 删除连接（检查是否有用途分配引用） |
| POST | /cloud-connections/:id/test | 测试连接（写入探测 → 回读 → 校验 → 删除） |
| POST | /cloud-connections/:id/toggle | 启用/禁用连接 |

#### 用途分配

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | /cloud-assignments | 列出所有用途分配 |
| PUT | /cloud-assignments | 批量更新用途分配（整体替换） |
| GET | /cloud-assignments/resolve/:usage | 查询指定用途的可用连接列表（按优先级排序） |

#### 存储状态

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | /storage/status | 获取存储状态（默认存储模式、各连接可用性、用途分配完整性） |

### 2.4 存储工厂重构

`StorageFactory` 需要从读取 `settings` 表改为读取 `cloud_connections` 表：

```typescript
interface StorageFactory {
  getLocal(): LocalStorage;
  getByUsage(usage: CloudUsage): Storage;
  getByConnectionId(connectionId: number): Storage;
  resolveReadable(input: { local_path: string | null; remote_key: string | null; connection_id: number | null; primary_location: 'local' | 'cloud' }): Promise<{ storage: Storage; key: string } | null>;
  isCloudAvailable(): boolean;
  getStorageStatus(): StorageStatus;
  refreshStorage(): StorageStatus;
  clearAllCaches(): void;
}
```

关键变化：

- `getByUsage(usage)` 根据用途分配表查找对应的连接配置，构建并缓存 Storage 实例。
- `getByConnectionId(connectionId)` 根据连接 ID 直接获取 Storage 实例。
- 缓存键从固定的 `'s3'` 改为按 `connectionId` 缓存。
- `isCloudAvailable()` 检查是否有至少一个已启用且配置完整的连接。

### 2.5 文件表字段调整

`book_files` 和 `book_covers` 表需要增加 `connection_id` 字段，用于记录该文件存储在哪个云端连接上：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `connection_id` | INTEGER | 引用 cloud_connections.id，记录文件存储在哪个云端连接上 |

写入云端时根据用途分配查找目标连接，写入后将 `connection_id` 记录到文件记录中。读取时根据 `connection_id` 定位到正确的连接配置。

## 第三部分：云备份操作（云备份页面职责）

### 3.1 设计目标

云备份页面负责管理**发送与接收动作**——即将数据发送到云端，或从云端拉取数据。

核心目标：

1. 将书籍管理中的"发送到云端"功能迁移到云备份页面。
2. 提供批量发送操作：选择本地文件 → 发送到已分配的云端连接。
3. 提供从云端拉取操作：选择云端文件 → 拉取到本地。
4. 展示同步状态总览：各数据类型的同步进度、待同步数量、失败数量。
5. 备份包上传到远端（复用连接配置，不再单独配置 OSS/WebDAV）。

### 3.2 页面结构

云备份 Tab 的内容重新组织为以下区块：

```
云备份页面
├── 同步状态总览（新增）
│   ├── 书籍文件：X 个已同步 / Y 个待同步 / Z 个失败
│   ├── 封面图片：...
│   └── 笔记：...
├── 发送到云端（从书籍管理迁入）
│   ├── 候选文件列表（local_only 或 sync_status != synced 的文件）
│   ├── 全选/按条件筛选
│   ├── 目标连接显示（根据用途分配自动确定，不可选）
│   └── 发送按钮 + 进度展示
├── 从云端拉取（新增）
│   ├── 云端文件列表（remote_key 存在但 local_path 为空或 sync_status != synced）
│   ├── 全选/按条件筛选
│   └── 拉取按钮 + 进度展示
├── 同步操作（新增）
│   ├── 补齐 dual 模式 pending 文件
│   ├── 手动触发全量同步
│   └── 重试失败的同步
└── 备份到云端（已有，适配新架构）
    ├── 备份模块选择
    ├── 备份目标选择（从已分配的 backup_db / backup_full 连接中自动读取，或多选）
    └── 上传进度
```

### 3.3 发送到云端

从书籍管理页面迁移而来。核心逻辑不变，但目标连接的确定方式从"检查 S3 配置是否完整"改为"查询用途分配表"。

流程：

```text
用户在云备份页面选择待发送文件
  ↓
后端查询文件的 storage_mode 和所属数据类型
  ↓
根据数据类型查询 cloud_usage_assignments 获取目标连接
  ↓
从本地读取文件 → 写入目标云端连接
  ↓
更新文件记录：storage_mode → dual, sync_status → synced, connection_id → 目标连接 ID
```

多目标场景：

如果某个用途分配了多个连接（如 `backup_db` 分配了 OSS + WebDAV），写入时按 priority 顺序依次写入所有目标。部分失败时标记 `partial_failed`，记录哪些目标成功、哪些失败。

### 3.4 从云端拉取

新增功能，从云端连接拉取文件到本地。

流程：

```text
用户在云备份页面选择待拉取文件
  ↓
后端根据文件记录的 connection_id 定位云端连接
  ↓
从云端读取文件 → 写入本地存储
  ↓
更新文件记录：local_path 填充, sync_status → synced
```

### 3.5 备份到云端

备份包上传到远端的功能，从原来"备份 Tab 内嵌 CloudStorageCard"改为"从用途分配中读取目标连接"。

流程变化：

- 不再需要在备份页面单独配置 OSS/WebDAV。
- 备份目标从 `cloud_usage_assignments` 中 `usage = 'backup_full'` 或 `usage = 'backup_db'` 的分配自动获取。
- 用户只需选择备份模块和备份类型（完整备份 / 数据库备份），目标连接自动确定。
- 如果备份用途分配了多个连接，备份包同时上传到所有目标。

### 3.6 同步状态管理

提供同步状态的查看与管理：

- 查看所有文件的同步状态分布（已同步 / 待同步 / 失败）。
- 查看单个文件的同步详情（哪个连接已同步、哪个待同步）。
- 手动触发单个文件或批量文件的同步重试。
- 同步失败的错误信息展示与排查指引。

## 第四部分：存储抽象层

### 4.1 存储接口

项目已建立统一的存储抽象接口 `Storage`，定义于 `apps/api/src/lib/storage.ts`：

```typescript
export interface Storage {
  readonly driver: 'local' | 's3' | 'webdav';

  putBytes(key: string, bytes: Buffer, opts?: StoragePutOptions): Promise<PutResult>;
  putStream(key: string, stream: StorageInputStream, opts?: StoragePutOptions): Promise<PutResult>;
  getStream(key: string, opts?: StorageGetOptions): Promise<NodeJS.ReadableStream>;
  getBytes(key: string): Promise<Buffer>;
  delete(key: string): Promise<void>;
  exists(key: string): Promise<boolean>;
  size(key: string): Promise<number>;
  move(srcKey: string, dstKey: string): Promise<void>;
  signedUrl(key: string, ttlSec: number): Promise<string>;
  publicUrl(key: string): string | null;
}
```

实现：

- `LocalStorage`：本地文件系统（已有）。
- `S3Storage`：S3 兼容对象存储（已有）。
- `WebDavStorage`：WebDAV 服务器（新增）。

### 4.2 WebDavStorage（新增）

需要实现 `WebDavStorage` 类，遵循 `Storage` 接口：

- 基于 `webdav` npm 包或原生 HTTP 请求实现。
- 支持 Put / Get / Delete / Exists / Size / Move。
- Signed URL 和 Public URL 对 WebDAV 可能不适用，返回 `null` 或抛出不支持错误。
- 认证支持 Basic Auth 和 Bearer Token。

### 4.3 三态存储模型（保留）

| 存储模式 | 含义 | 写入行为 | 读取行为 |
| --- | --- | --- | --- |
| `local_only` | 仅保存在当前设备 | 写入本地 | 读取本地 |
| `cloud_only` | 仅保存在云端 | 写入云端（按用途分配的目标连接） | 读取云端 |
| `dual` | 本地和云端都保留 | 写入主端，另一端标记 `pending` | 优先读取主端 |

### 4.4 多目标写入

当某个用途分配了多个连接时，写入逻辑：

```text
获取用途分配的所有连接（按 priority 排序）
  ↓
遍历每个连接
  ↓
  写入该连接
  ↓
  记录成功/失败
  ↓
更新文件记录：
  - 所有目标成功 → sync_status = 'synced'
  - 部分失败 → sync_status = 'partial_failed'，记录失败的 connection_id 和错误信息
  - 全部失败 → sync_status = 'failed'
```

读取逻辑：

```text
获取用途分配的所有连接（按 priority 排序）
  ↓
按优先级逐个尝试 exists()
  ↓
返回第一个可用的 Storage + key
```

## 第五部分：职责划分与页面整合

### 5.1 存储页面 vs 云备份页面

| 维度 | 存储页面 | 云备份页面 |
| --- | --- | --- |
| 核心职责 | 管理连接配置、数据路由 | 管理发送/接收动作 |
| 用户心智 | "数据往哪存" | "把数据送过去 / 拉回来" |
| 操作对象 | 连接配置条目、用途分配 | 文件列表、备份包 |
| 操作频率 | 低频（配置一次长期使用） | 中频（定期同步、备份） |
| 关键操作 | 创建/编辑/删除连接、测试连接、设置用途分配 | 发送到云端、从云端拉取、备份到云端、同步状态管理 |

### 5.2 页面整合方案

**方案 A：保持两个 Tab 分离**（推荐）

存储 Tab 管理连接配置和数据路由，云备份 Tab 管理发送/接收动作。职责清晰，用户心智模型明确。

**方案 B：整合为一个 Tab**

如果用户反馈两个 Tab 切换不便，可以整合为一个"云端"Tab，内部用子导航或分区组织：

```
云端页面
├── 连接配置区（折叠面板）
├── 数据路由区（折叠面板）
├── 同步操作区
└── 备份操作区
```

建议第一版采用方案 A，后续根据用户反馈决定是否整合。

### 5.3 书籍管理页面的变化

当前书籍管理页面的"批量操作 > 发送到云端"功能迁移到云备份页面后，书籍管理页面的变化：

- 移除"发送到云端"按钮。
- 保留文件列表中的存储位置和同步状态展示。
- 文件上传时的 storage_mode 选择保留（根据默认存储模式自动选择，用户可覆盖）。
- "文件发送"功能由云备份页面统一管理。
