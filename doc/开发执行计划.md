## 文档说明

- 本文档规定"按什么顺序做、每步达成什么"。产品定义见《需求总纲》，功能范围见《功能清单》，技术路线见《技术方案》，数据结构见《数据模型》，接口契约见《API 接口》。
- **第一部分 里程碑**：每个里程碑列出达成目标，对应技术方案的 Step/Phase。
- **第二部分 执行项**：按开发顺序排列，从技术角度拆解；每项标注覆盖的《功能清单》条目（如 1.01）。功能点被拆成技术执行项，一个功能点可能跨多项，一项也可能覆盖多个功能点。
- **粒度策略**：M0/M1（近期）执行项细化到可直接开工；M2–M5 按模块粒度列出，临近时再细化为可执行步骤（遵循 YAGNI，避免远期过度规划返工）。
- 执行项编号规则：`M{里程碑}-{序号}`，如 M1-03。
- 版本号遵循三段式「主.次.修订」，递增规则见《决策记录》版本号规范。

# 第一部分 · 里程碑

## M0 — 工程地基

**对应**：Phase 1 / Step 1 前置

**达成目标**：一个可登录、可部署、可跑通数据库迁移的空壳应用。前后端骨架、Docker、鉴权、通用约定全部就位，为 M1 提供稳定底座。

- pnpm monorepo 工作区搭建完成（apps/web、apps/api、packages/shared、packages/db）
- Fastify 后端可启动，健康检查、日志、配置加载就绪
- Vite + React + shadcn/ui 前端壳，套用现有设计稿暖色主题与侧边栏
- better-sqlite3 + Drizzle 接入，迁移机制跑通
- 单账户鉴权可用（登录/登出/会话 Cookie/密码哈希）
- Docker + docker-compose 一键启动，数据卷挂载
- 通用约定落地：响应包装、分页、错误处理、Zod 校验

**完成标志**：`docker compose up` 后浏览器可打开登录页，登录成功进入空书架壳，数据库迁移已执行。

**当前实现备注（2026-06-27）**：

- M0 工程地基已搭建：pnpm monorepo、Fastify API、Vite React 前端壳、Drizzle + better-sqlite3 迁移、Dockerfile/docker-compose、本地启动脚本均已建立。
- 后端单账户鉴权链路仍按 M0-05 保留：`users` 表、argon2、Cookie session、`/auth/setup`、`/auth/login`、`/auth/logout`、`/auth/me`。
- 为便于先推进 M1 书架功能，本地开发模式临时免登录：`VITE_AUTH_DISABLED=true` 时前端直接进入空书架壳；生产构建默认不免登录。
- Docker Compose 运行前必须提供强随机 `SESSION_SECRET`，避免生产环境使用默认弱密钥。
- M1 的书籍 CRUD、文件上传、分类标签、回收站、导出备份、OPDS 等尚未开始，不应将 M0 空书架壳视为完整书架管理。

## M1 — 书架与文件管理

**对应**：Phase 1 / Step 1 核心

**达成目标**：完整的书库管理能力，除"打开阅读"外全部可用。地基层全部就位，各模块入口预留，为 M2 阅读器进场扫清依赖。

- S1 数据模型全套表与索引、FTS5 迁移上线
- 书籍全生命周期：录入、编辑、详情、列表、搜索、筛选、排序、分页、批量
- 分类、标签、评分、可见性、阅读目的、书籍关联、重复检测
- 五状态体系 + 状态变更历史 + 回收站
- 文件管理全链路：上传、多文件、主文件、下载、替换、删除、封面抽取
- 导出与备份：元数据导出、文件下载、全量 ZIP、SQLite 自动备份
- OPDS 1.2 输出，KOReader 实测兼容
- 概览首页核心、设置页、暗色模式、空状态引导
- 阅读器/主题/AI 入口预留

**完成标志**：可完整管理一个真实书库——录入书籍、上传 EPUB、分类标签、改状态、回收站恢复、导出元数据、OPDS 订阅下载，全部跑通；仅"打开阅读"为灰置。

---

## M2 — 阅读器与笔记沉淀

**对应**：Phase 1 / Step 2

**达成目标**：可在线阅读 EPUB，产出高亮/划线/笔记/进度，可跳回原文。沉淀层核心就位。

- epub.js 集成，打开主 EPUB、目录、翻页
- CFI 进度保存/恢复
- 高亮/划线（CFI + 原文兜底）、附注增删改、点击查看
- 独立笔记（TipTap 富文本，可导出 Markdown）
- 跳回原文（笔记/高亮 → 阅读器定位）
- 标记体系（重要/疑问/启发，预留扩展）
- 单书阅读痕迹汇总、笔记全文搜索（FTS5）
- 详情页"阅读"按钮激活，笔记/高亮导出激活

**完成标志**：打开一本书可阅读、划高亮、写笔记、关书再开回到原位、从笔记跳回原文。

---

## M3 — AI 辅助（阶段一）

**对应**：Phase 1 / Step 3

**达成目标**：AI 提供管理辅助与阅读辅助，回答带引用，生成内容作为派生资产隔离存放。

- `AIService` 接口落地，可配置 LLM provider/key/模型
- 录入辅助（元数据补全/标签建议/分类建议/重复发现）
- 阅读辅助（高亮/笔记/章节摘要、问题整理）
- 引用追溯（书 + 章节），结果存为 ai_assets 与用户内容隔离

**完成标志**：配置 AI key 后，可对一本书生成带引用的摘要，结果单独存放、与手写笔记区分展示。

---

## M4 — 主题阅读 + AI RAG

**对应**：Phase 2

**达成目标**：主题组织跨书材料；AI 可基于个人书库做语义问答与主题分析。

- 主题 CRUD + 软引用书籍/高亮/笔记/章节片段
- 主题沉淀内容（问题/判断/比较）、主题内汇总检索
- 嵌入 + sqlite-vec，RAG 书库级问答、主题分析
- 概览统计核心激活（高亮/笔记数量、阅读沉淀）

**完成标志**：可创建主题、关联多书痕迹、AI 基于书库回答问题并标注出处。

---

## M5 — 增强与深化

**对应**：Phase 3（多项待《决策记录》定位确认）

**达成目标**：分级访问、云同步、阅读器与统计增强按定位排期落地。

- AI 分级访问（9.18）
- 对象存储云同步（8.05）
- 阅读器增强项（3.21–3.31，待定位）
- rclone / Google Drive / Dropbox 可选（8.06，待定位）
- 阅读统计增强（5.09–5.17，待定位）

**完成标志**：按确认的增强边界逐项交付。
