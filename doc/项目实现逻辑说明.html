1. 项目总体结构

Redesk 当前是一套单仓全栈应用。前端负责书架管理、详情编辑、文件操作、概览与设置；后端负责业务 API、文件处理、封面处理、存储抽象和系统维护；共享类型和数据库 schema 独立放在 packages。

前端应用 apps/web
后端应用 apps/api
共享类型与校验 packages/shared
数据库 schema 与迁移 packages/db
React Router TanStack Query Fastify Drizzle ORM better-sqlite3 本地存储 + S3 抽象 Route A 全栈 TypeScript

2. 目录职责分层

前端层

  • src/App.tsx：路由装配。
  • src/routes/：页面级容器，负责组合组件与 hooks。
  • src/components/：共享业务组件与 UI 外壳。
  • src/hooks/：全部前端数据访问层，统一通过 React Query 发请求。
  • src/lib/：API 客户端、query client、认证模式、工具函数。

后端层

  • src/server.ts：创建并注册 Fastify 服务。
  • src/routes/：按业务域组织路由。
  • src/lib/：认证、存储、元数据抓取、设置读取等业务工具层。
  • src/config.ts：环境与路径配置。
  • src/db.ts：Drizzle 与 SQLite 入口。

前端的核心不是“页面很多”，而是层次很清晰：路由页负责组装，业务组件负责交互，hooks 负责数据，lib 负责底层基础设施。

6. 数据模型导览与业务对应

数据模型定义在 packages/db/src/schema/。这一节把原来的数据模型导览内容并入主手册，先讲读表需要的概念和约束，再讲当前仓库里已经存在的表及其业务位置。

6.1 概念速查

主键 id

每条记录的唯一编号，路由跳转、关联查询、编辑保存都会依赖它。

外键 *_id

表示“我属于谁”或“我引用谁”，例如 book_files.book_id 指向书籍主表。

软删除 deleted_at

不是物理删除，而是打上回收站时间戳，当前在 books 上承担回收站能力。

JSON 字段

用于弹性存储结构化内容，例如 books.custom_attributes 和 settings.value。

唯一约束

用于防止重复数据，例如标签重名、分类重名、某些关联重复挂接。

owner_id

表示数据归属用户。当前单用户场景下值通常一致，但查询边界和表结构已为多人预留。

状态枚举

例如 books.status，决定书架筛选、概览统计和状态流转记录。

关联桥表

book_tags 这类表只负责连接两端实体，本身不承载完整业务档案。

6.2 数据设计约束

分类与删除边界

  • 一书一分类，主用途只落一个 category_id。
  • “存档/存”是书籍状态，不等于删除。
  • 回收站走 deleted_at，和状态筛选是两条逻辑。

归属与扩展边界

  • 根实体通过 owner_id 保留多用户扩展空间。
  • 扩展属性优先走 custom_attributes 或 settings.value，避免频繁改表。
  • 共享契约字段名需要同步 packages/shared。

6.3 当前表关系分层

层次当前表作用关系说明
用户层users账号、管理员与密码信息是数据归属和权限判断的源头。
书籍核心层books书名、作者、状态、来源、可见性等主档案当前系统的核心枢纽，多数业务都围绕它展开。
组织辅助层categories、tags、book_tags完成分类和多标签组织categories 是一对多，book_tags 负责多对多桥接。
文件资产层book_files、book_covers保存阅读文件、封面来源和封面状态文件与封面都挂在书籍主资产之下，封面还可关联到具体文件。
关系与历史层book_relations、status_history记录书与书之间的关系，以及状态变更历史不改变书籍主档案，但补足横向关联和时间轴。
系统配置层settings存放系统配置、用户配置、存储设置等不是按页面拆表，而是按键值统一承载。
阅读预留层bookmarks阅读定位相关数据当前已存在表结构，但前端完整阅读留痕闭环尚未展开。

6.5 与业务最相关的字段

books.status

决定书架筛选、概览状态分布、状态时间线写入。

books.deleted_at

控制回收站与软删除，不应与正式业务状态混用。

books.custom_attributes

用于不想频繁改表的自定义属性扩展。

book_files.book_id

为 null 时表示未关联文件池中的文件。

book_files.is_primary

决定主阅读文件，阅读入口和部分展示逻辑会优先依赖它。

book_files.storage_mode

决定本地、云端或双端存储，与 primary_location、sync_status 配合使用。

book_covers.is_active

用于多封面来源场景下选择当前生效封面。

categories.type

区分个人分类与类型分类，前端不同入口会按类型过滤。

settings.key

多用户开关、默认存储方式、云端配置、AI 配置都以键值形式落在这里。

7. 关键实现流程

7.1 书籍录入与编辑

1
前端入口主要在 routes/bookshelf.tsx 的建书流程，以及 components/book-detail-sheet/page.tsx 的详情内联编辑；拆分后的子模块在同目录继续下钻。
2
表单统一通过 hooks/use-books.ts 发送到 /books 或 /books/:id。
3
routes/books.ts 承担参数校验、owner 边界、标签同步、状态历史写入和返回结构整形。
4
前端通过 React Query 失效和刷新相关缓存，让书架、详情、概览同步更新。

7.2 文件上传、文件池与主文件

1
上传入口分为两类：书籍详情中直接上传到某本书，或文件库中先上传为未关联文件。
2
前端通过 useUploadFile 或 useUploadUnassociatedFile 发送 FormData。
3
后端 routes/files.ts 调用内部保存逻辑，按 storage_mode 写本地、云端或双端，并生成 book_files 记录。
4
未关联文件后续可通过匹配接口挂到具体书籍；主文件状态也在 book_files 里维护。

7.3 封面来源与切换

1
封面来源有三类：EPUB 自动抽取、来源链接抓取、用户手动上传。
2
三类来源统一写入 book_covers，并通过 is_active 标记当前生效封面。
3
书籍详情抽屉用 useBookCovers 拉取后分组展示，并支持切换、删除和新增来源。

7.4 元数据抓取与字段应用

1
用户在详情页保存 source_url 后触发抓取。
2
后端通过 lib/book-metadata.ts 获取标题、作者、出版信息、封面 URL 等。
3
前端弹窗对比“抓取值”和“当前值”，由用户勾选要应用的字段。
4
后端只写回勾选字段，并可选同步抓取封面，避免全量覆盖已有资料。

7.5 认证、公开书架与受保护页面

1
App.tsx 将根书架页和回收站放在 PublicShell 下，后台页面放在 RequireAuth 下。
2
useCurrentUser 负责确认登录态，用户对象通过 ShellUserContext 下发给页面和侧栏。
3
前端只是根据后端返回的用户状态调整展示，真正的权限边界仍由后端接口负责。

7.6 设置、存储与系统维护

1
设置页虽然是一个页面，但底层分成三组数据：通用配置、存储配置、系统维护。
2
通用配置走 /settings；存储走 /storage/*；系统维护走 /system/*。
3
云端存储状态不是单纯读库，而是由后端结合配置与驱动能力动态计算后返回。
