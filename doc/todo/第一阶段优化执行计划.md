## 1. 优化目标与原则

## 1.1 优化目标

本轮不是继续加功能，而是解决以下工程问题：

- 当前前端语法错误导致无法通过检查。
- 存储模型的命名、文档、真实行为分叉。
- 系统级设置与用户归属边界混乱。
- 自动化测试几乎缺位。
- 关键前端文件过大，后续维护成本偏高。

## 1.2 执行原则

- 先修“无法校验”，再修“语义不一致”，最后修“结构质量”。
- 每一批结束都必须能跑通 `typecheck` 与 `lint`。
- 文档、接口、实现必须同步收口，不允许只改其中一层。

## 2. 第一批：先恢复可校验状态

> 目标：先把当前工作区从“前端无法通过类型/语法检查”恢复到“可继续开发”的状态。

### 2.1 必做项

| 编号 | 执行项 | 输出/验收 |
| --- | --- | --- |
| O1-01 | 修复 `apps/web/src/routes/settings.tsx` JSX 语法错误 | `apps/web` typecheck 通过 |
| O1-02 | 修复同文件导致 ESLint 解析失败的问题 | ESLint 不再报 parsing error |
| O1-03 | 回归设置页基础路径：设置读取、保存、备份区、系统信息区可正常渲染 | 页面可正常打开，无白屏 |

### 2.2 同批顺手修复项

| 编号 | 执行项 | 输出/验收 |
| --- | --- | --- |
| O1-04 | 评估并修复 `react-refresh/only-export-components` 两个 warning | warning 清零或明确保留理由 |
| O1-05 | 清理本批直接阻断校验的低级语法/类型错误 | `pnpm typecheck`、`pnpm lint` 可作为后续基线 |

### 2.3 第一批验收标准

- `apps/api` typecheck 通过
- `apps/web` typecheck 通过
- `eslint` 至少不再有解析错误
- 设置页可打开并完成基本交互

## 3. 第二批：收口存储语义与系统边界

> 目标：解决当前“字段名看起来支持、实际行为没闭环”的问题，同时清理系统级设置与用户级归属混用的问题。

### 3.1 存储语义收口

| 编号 | 执行项 | 输出/验收 |
| --- | --- | --- |
| O2-01 | 明确 `local_only / cloud_only / dual` 的正式语义，并同步到数据模型、API 文档、设置页文案 | 文档一致 |
| O2-02 | 逐条核对 `saveUploadedFile`、封面上传、远程封面抓取、下载、删除、替换等路径是否真正遵守三态语义 | 所有主链路语义一致 |
| O2-03 | 对 `dual` 做二选一决策：要么补成真实双写，要么在当前阶段降级为未完成能力并调整文案/入口 | 不再出现“文档支持但行为不支持” |
| O2-04 | `sync_status` 必须只表达真实状态，不允许默认把未双写完成的数据写成 `synced` | 状态可被信任 |

### 3.2 系统级设置边界收口

| 编号 | 执行项 | 输出/验收 |
| --- | --- | --- |
| O2-05 | 梳理所有 `owner_id = 1`、`user_id = 1` 的系统级硬编码点 | 形成清单 |
| O2-06 | 设计并实现系统级配置作用域：明确哪些是 system scope，哪些是 user scope | 不再依赖“1 号用户假设” |
| O2-07 | 同步调整设置、存储、系统重置、系统统计等接口实现 | 系统接口边界一致 |

### 3.3 第二批验收标准

- 存储三态语义在代码、接口、文档中一致。
- `dual` 不再是伪完成状态。
- 系统级配置不再隐式绑定到 1 号用户。

## 4. 第三批：补测试与性能基础

> 目标：给当前最容易回归的模块加最小必要护栏，并收掉已确认的性能劣化点。

### 4.1 测试优先级

| 编号 | 执行项 | 输出/验收 |
| --- | --- | --- |
| O3-01 | 为文件上传/删除/替换/匹配主链路补 API 层测试 | 文件链路有回归护栏 |
| O3-02 | 为存储模式判定与状态写入补单测 | 三态逻辑可验证 |
| O3-03 | 为认证关键路径补测试：登录、改密、高风险操作确认前置校验 | 安全链路可验证 |
| O3-04 | 为批量操作与单本操作的一致性补测试 | 状态、时间字段行为一致 |

### 4.2 性能基础优化

| 编号 | 执行项 | 输出/验收 |
| --- | --- | --- |
| O3-05 | 清理 categories/tags/overview 中明显的 N+1 查询 | 查询次数下降 |
| O3-06 | 统一概览、文件页统计口径，避免当前页统计冒充全量 | 统计可信 |
| O3-07 | 补齐时间字段格式约束，避免非 ISO UTC 字符串混入 | 时间字段可排序、可统计 |

### 4.3 第三批验收标准

- 至少覆盖上传、存储模式、认证、批量操作四类测试。
- 已确认的 N+1 点完成收口。
- 时间字段约束和统计口径一致。

## 5. 第四批：前端结构拆分

> 目标：把已经超重的页面拆成稳定结构，降低后续回归风险。

### 5.1 拆分对象

| 编号 | 执行项 | 输出/验收 |
| --- | --- | --- |
| O4-01 | 拆分 `apps/web/src/routes/settings.tsx`：系统信息、备份、存储配置、账号安全分离 | 主路由文件显著瘦身 |
| O4-02 | 拆分 `apps/web/src/routes/bookshelf.tsx`：筛选条、列表区、批量操作区、弹窗区分离 | 书架页结构清晰 |
| O4-03 | 拆分 `apps/web/src/components/book-detail-sheet.tsx`：详情头部、元信息区、文件区、封面区、标签区分离 | 详情抽屉更易维护 |

### 5.2 拆分要求

- 先拆视图和状态边界，不做无关视觉改版。
- 拆分后保持对外行为不变。
- 拆分过程中同步清理明显的类型漂移和状态串联问题。

### 5.3 第四批验收标准

- 三个超大文件完成结构拆分。
- 主要业务状态迁移到更清晰的 hooks / 子组件边界。
- 拆分后 `typecheck`、`lint`、核心页面回归通过。

## 6. 执行顺序自检

### 6.1 顺序原因

- 第一批必须最先做，否则后续每一步都缺乏校验基线。
- 第二批在第一批之后做，因为需要稳定编辑环境和真实检查结果。
- 第三批建立护栏，防止第二批收口后再次漂移。
- 第四批最后做，避免在语义未稳定前先大拆结构。

### 6.2 每批固定验收动作

每一批完成后都执行：

- `pnpm typecheck`
- `pnpm lint`
- 如涉及构建链路或运行时页面入口，再执行 `pnpm build`

### 6.3 交付完成标准

满足以下条件，才算本轮优化完成：

- 前端不再存在阻断性语法/类型错误。
- 存储语义、系统边界、状态字段都可被文档和代码一致解释。
- 核心链路具备最小必要测试护栏。
- 超重页面文件完成第一轮结构拆分。
