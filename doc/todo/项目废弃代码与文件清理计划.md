> 生成日期：2026-07-04
> 目的：识别并清理项目中废弃、过时或不再需要的代码和文件，保持项目整洁

## 一、清理范围概述

经过对项目结构的全面分析，识别出以下几类可清理的内容：

| 类别 | 数量 | 风险等级 | 说明 |

| 过时交接文档 | 2 文件 | 低 | 已完成的历史交接记录 |

## 二、详细清理清单

### 2.1 历史设计原型（doc/Archive/）

**目录**：`doc/Archive/`

**包含内容**：
- `bookshelf-optimize-v2/` - 书架页面优化方案 B 的 HTML 静态示例（10 个文件）
- `redesk-ui/` - Redesk UI 设计稿（7+ 文件）
- `webDesing/` - 网页设计稿（3 个 HTML 文件）
- 6 个独立的 PNG 图片文件
- `README.md` - Archive 说明文件

**清理理由**：
1. `doc/Archive/README.md` 明确声明："归档文件不作为当前实现依据"
2. 这些文件是早期创始文档和历史草案，仅保留产品讨论的来源脉络
3. 当前实现依据已有明确优先级列表（AGENTS.md > 决策记录 > 需求总纲等）
4. 这些 HTML 原型已被实际代码实现取代，不再需要作为参考

**影响评估**：
- **功能影响**：无 - 这些文件不参与构建、运行或测试
- **文档影响**：无 - 当前实现依据文档完整
- **历史价值**：低 - 产品讨论脉络已在决策记录中保留
- **风险**：极低 - 删除后不影响任何现有功能

**建议操作**：
- 删除整个 `doc/Archive/` 目录
- 或者如果需要保留历史记录，可以压缩存档到项目外

## 七、注意事项

1. **不要清理正在使用的设计文档** - 如果某个设计文档仍被引用或参考，不要删除
2. **保留 git 历史** - 所有删除的文件都已在 git 历史中保留，可随时恢复
3. **分批清理** - 建议分批清理，每批验证后再进行下一批
4. **标记而非删除** - 对于不确定的文件，可以先标记为"待清理"而非直接删除
5. **文档更新** - 清理后更新相关文档的引用（如有）
