## 1. 目标

实现 Redesk 新一代备份恢复系统：

1. 以模块为核心组织备份与恢复。
2. 提供系统备份、书籍备份、阅读/笔记备份、主题备份、全量备份等预设组合。
3. 所有模块在 UI 中完整展开，预设只负责快速勾选。
4. 备份包包含 `manifest.json`，记录版本、时间、模块、数量、体积、敏感标记、风险提示和文件清单。
5. 备份目标支持本地下载、OSS、WebDAV。
6. OSS / WebDAV 上传提供进度状态。
7. 恢复前必须读取 manifest 并完成预检。
8. 恢复默认保守，用户确认前不修改当前实例。

## 2. 总体实现策略

### 2.1 分阶段交付

本功能涉及后端备份服务、共享协议、前端设置页、远端上传、恢复预检、模块恢复和数据库快照恢复。为避免一次性改动过大，按以下阶段推进：

1. **阶段 A：协议与模块模型**  
   建立共享 schema、模块 ID、预设、manifest、备份目标和任务状态类型。

2. **阶段 B：模块化备份生成**  
   实现备份预览、模块导出、manifest 生成、本地下载 ZIP。

3. **阶段 C：备份目标与进度**  
   支持 OSS / WebDAV 保存备份包，并提供任务状态与上传进度。

4. **阶段 D：前端备份 UI**  
   在设置页提供预设组合、模块勾选、摘要、目标选择和进度展示。

5. **阶段 E：恢复预检**  
   上传备份包、读取 manifest、校验模块与文件清单，返回可恢复摘要。

6. **阶段 F：基础模块恢复**  
   先支持系统设置、书库数据、分类标签、文件索引的模块恢复。

7. **阶段 G：扩展恢复能力**  
   支持阅读数据、书籍文件本体、数据库快照覆盖恢复。

8. **阶段 H：后置能力**  
   主题阅读恢复、用户登录配置恢复、高级冲突策略、后台任务持久化、云端自动拉取。

### 2.2 第一阶段建议落地范围

第一轮开发建议完成到阶段 E，并至少实现系统设置模块恢复：

- 共享 schema；
- 备份预览；
- 模块化备份包生成；
- `manifest.json`；
- 本地下载；
- OSS / WebDAV 目标与进度；
- 前端备份 UI；
- 恢复预检；
- 系统设置恢复。

书库数据、阅读数据、文件本体和数据库快照恢复可进入第二轮，但第一轮的备份包结构必须为这些能力预留完整信息。

```ts
  'settings.public',
  'settings.secrets',
  'users.auth',
  'library.books',
  'library.taxonomy',
  'library.relations',
  'assets.file_index',
```

```ts
  'reading.highlights',
  'reading.notes',
  'reading.bookmarks',
  'topics.workspace',
  'database.snapshot',
] as const;

export const backupModuleIdSchema = z.enum(BACKUP_MODULE_ID_VALUES);
export type BackupModuleId = z.infer<typeof backupModuleIdSchema>;

export const backupTargetSchema = z.discriminatedUnion('type', [
  z.object({ type: z.literal('download') }),
  z.object({ type: z.literal('oss'), remote_path: z.string().min(1).max(1024).optional() }),
  z.object({ type: z.literal('webdav'), remote_path: z.string().min(1).max(1024).optional() }),
]);
```

## 8. 风险与处理

### 8.1 大备份包内存占用

风险：一次性在内存中构造 ZIP 或远端上传会导致内存占用过高。

处理：

- 使用 stream 方式打包；
- 本地临时文件作为 OSS / WebDAV 上传源；
- 上传完成后清理临时文件；
- 大包默认走后台任务。

### 8.2 远端上传失败

风险：OSS / WebDAV 网络中断导致备份未完成。

处理：

- 任务状态进入 `failed`；
- 保留本地临时备份包一段时间；
- 前端展示失败原因；
- 错误中不得包含密钥。

### 8.3 敏感配置泄露

风险：manifest、日志、错误响应中暴露密钥。

处理：

- manifest 只标记包含敏感配置，不展示明文；
- 日志和错误响应脱敏；
- `settings.secrets` 默认不备份、不恢复；
- 恢复敏感配置必须二次确认。

### 8.4 模块恢复 ID 错配

风险：不同实例自增 ID 不一致，导致笔记、高亮挂错书。

处理：

- 使用 stable key；
- 书籍匹配综合 ISBN、书名作者、source_url、主文件 checksum；
- 低置信度匹配跳过并写入报告；
- 不做静默错误恢复。

### 8.5 数据库快照覆盖风险

风险：快照恢复覆盖当前实例。

处理：

- 管理员权限；
- 二次确认；
- 执行前保护备份；
- 失败回滚；
- 必要时提示手动重启。
