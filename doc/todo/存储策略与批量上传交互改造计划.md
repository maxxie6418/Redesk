# 存储策略与批量上传交互改造计划

> 目标：在不改变 Redesk“本地优先、云端可选增强”总原则的前提下，把文件上传从“全局单一存储驱动”改造成“默认存储方式 + 批量上传时可逐本覆盖”的交互与数据模型。

## 1. 方案结论

### 1.1 已确认的交互方向

- 系统设置页提供一个**默认存储方式**
- 默认存储方式至少支持三种：
  - `仅保存在当前设备`
  - `仅保存在云端`
  - `本地和云端都保留`
- 批量上传时：
  - 先带出系统默认值
  - 允许用户对**每本书单独修改**
  - 若用户不改，则沿用默认值
- 书籍详情页、文件列表页都要展示文件的**实际存储状态**

### 1.2 交互语义

- “默认存储方式”是长期偏好
- “上传时修改”是本次上传的覆盖，不反写系统默认值
- 用户看到的是业务文案，不直接暴露 `local / s3 / dual` 这类底层词

### 1.3 当前实现与改造目标的差异

当前项目已有：

- `book_files.storage_driver`
- `book_covers.storage_driver`
- 本地存储与 S3 存储读写抽象
- 全局 `storage_driver` 配置与状态接口

当前缺少：

- 三态存储模式的完整表达
- “双端并存”状态表达
- 批量上传逐本覆盖的交互与接口能力
- 文件实际落点与同步状态的清晰展示

---

## 2. 本次改造范围

## 2.1 包含

- 设置页默认存储方式配置
- 批量上传弹窗的默认值与逐本覆盖交互
- 后端支持按文件/按书单次指定存储方式
- 数据模型支持三种模式与真实落点状态
- 书籍详情页 / 文件列表页的状态展示
- 云配置不完整时的禁用与提示

## 2.2 不包含

- 在线数据库同步
- 跨设备实时同步
- 复杂后台任务中心
- 自动补偿重试系统的完整建设
- 存储策略之外的阅读器/AI 功能改动

---

## 3. 交互设计要求

## 3.1 设置页

新增或调整“云存储 / 文件存储”区域，至少包含：

- 默认存储方式
- 云存储配置状态
- 连接测试
- 当前默认策略说明

要求：

- 默认值清晰可见
- 云未配置完成时，云相关模式不可作为默认值保存，或保存后需明确提示不可生效

## 3.2 批量上传弹窗

### 基本行为

- 上传弹窗打开时，先读取系统默认存储方式
- 每个文件项或每个待创建/待匹配的书籍项，都显示当前采用的存储方式
- 用户可逐项切换：
  - 仅本地
  - 仅云端
  - 双端保留

### 推荐布局

- 顶部显示“本次默认沿用系统设置”
- 文件/书籍列表中，每项右侧有一个轻量下拉或分段选择器
- 若整批都不改，用户直接上传
- 若部分要改，用户在对应项上单独覆盖

### 约束

- 第一版只支持“上传时逐项选择”
- 不要求做拖拽批量多选后统一改值
- 不要求做复杂批量编辑工具条

## 3.3 状态展示

书籍详情页、文件列表页至少支持以下状态文案：

- 仅本地
- 仅云端
- 本地 + 云端
- 双端同步中
- 双端部分失败

要求：

- 展示的是**实际状态**
- 不是只展示“上传时用户选了什么”

---

## 4. 数据模型改造建议

## 4.1 目标

当前单个 `storage_driver` 无法准确表达“双端并存”，需要补充字段。

## 4.2 book_files 建议字段

在 `book_files` 上引入或调整为以下语义：

- `storage_mode`
  - `local_only`
  - `cloud_only`
  - `dual`
- `local_path`
  - 本地存在时有值
- `remote_key`
  - 云端存在时有值
- `primary_location`
  - `local` 或 `cloud`
- `sync_status`
  - `synced`
  - `pending`
  - `partial_failed`
  - `failed`

## 4.3 book_covers 建议同步改造

`book_covers` 与 `book_files` 保持同类语义，避免封面仍停留在旧模型。

## 4.4 兼容策略

迁移旧数据时：

- 旧 `storage_driver = local` -> `storage_mode = local_only`
- 旧 `storage_driver = s3` -> `storage_mode = cloud_only`
- 历史数据的 `local_path / remote_key / primary_location / sync_status` 需补齐合理默认值

## 5. 后端改造计划

## 5.1 配置层

调整存储设置接口与配置项：

- 新增默认存储方式设置
- 保留现有云配置项
- `GET /storage/status` 返回：
  - 默认存储方式
  - 云是否可用
  - 云配置是否完整
  - 若不可用，给出原因

## 5.2 上传接口

改造文件上传相关接口，使其支持单次指定存储方式。

建议方式：

- `POST /books`
  - 若是 multipart 创建带文件
  - 新增字段表达本次文件存储方式
- `POST /books/:id/files`
  - 支持指定该文件的存储方式
- `POST /files/unassociated`
  - 支持指定存储方式

若批量导入流程内部会逐个创建/关联文件，也需能把每项存储方式透传到后端。

## 5.3 写入规则

### `local_only`

- 仅写本地
- 写库记录本地落点

### `cloud_only`

- 仅写云端
- 写库记录云端落点
- 云失败则整项失败

### `dual`

- 两端都写
- 成功时记录双端落点与 `synced`
- 若主端成功、副端失败：
  - 记录真实可用状态
  - 标记 `partial_failed`
  - 返回前端明确结果

## 5.4 读取规则

- 优先按 `primary_location` 读取
- 若主位置不可用，可视实现决定是否回退另一端
- 第一版即使不做自动回退，也要给出明确错误

## 5.5 删除与替换

删除文件时应按实际落点删除：

- 仅本地：删本地
- 仅云端：删云端
- 双端：两端都删

替换文件时也要遵守原有存储模式，或允许前端指定新模式。

## 6. 前端改造计划

## 6.1 设置页

修改设置页的云存储区域：

- 加入“默认存储方式”单选
- 展示云配置状态
- 云不可用时提示影响范围

## 6.2 批量上传弹窗

目标行为：

- 进入弹窗时，每项默认带出系统默认值
- 用户可以逐项切换
- 上传提交时，每项携带自己的存储方式

页面元素建议：

- 顶部说明“以下存储方式仅影响本次上传”
- 每项文件/书籍卡片展示：
  - 文件名
  - 匹配状态
  - 当前存储方式
  - 存储方式切换控件

## 6.3 书籍详情页

新增或调整文件状态展示区域：

- 主文件当前存储状态
- 其它关联文件当前存储状态
- 若双端部分失败，要有明显提示

## 6.4 文件列表页

文件列表中增加一列或一个状态标签：

- 仅本地
- 仅云端
- 本地 + 云端
- 同步中
- 部分失败

可选增强：

- 按存储状态筛选

第一版可不做筛选。

## 8. 测试与验收

## 8.1 后端测试

至少覆盖：

- `local_only` 上传成功
- `cloud_only` 上传成功
- `dual` 上传双端成功
- `dual` 上传主端成功、副端失败
- 云未配置时拒绝 `cloud_only` / `dual`
- 删除时按实际落点清理
- 替换时状态与落点正确更新

## 8.2 前端验收

至少验收：

- 设置页可保存默认存储方式
- 批量上传时自动带出默认值
- 可逐项修改存储方式
- 提交后每项按各自方式上传
- 详情页与文件列表页显示真实状态
- 云未配置时，云端选项禁用或显式报错

## 8.3 回归检查

必须回归：

- 现有单文件上传
- 创建书籍时带文件
- 未关联文件池
- 文件替换
- 文件下载
- 封面上传 / 封面抽取 / 封面读取

---

1. 数据模型与迁移设计
2. `packages/shared` 类型与 schema 更新
3. 后端存储设置接口改造
4. 后端上传 / 删除 / 读取逻辑改造
5. 设置页 UI 改造
6. 批量上传弹窗逐项覆盖能力
7. 详情页 / 文件列表状态展示
8. 文档同步
9. 类型检查 / lint / 全链路验证

---

## 10. 给执行 AI 的明确要求

- 不要把本次方案简化回“全局只选 local 或 s3”
- 不要把“双端保留”偷换成“上传到主端后顺手备份一下”但库里仍只有单落点
- 不要只改前端文案，不改数据模型和后端语义
- 不要让“本次上传覆盖”反写系统默认设置
- 不要在第一版引入过重的任务系统或复杂后台面板
- 代码完成后，至少运行：
  - `pnpm typecheck`
  - `pnpm lint`
- 若涉及构建链路或前端打包行为变化，再运行：
  - `pnpm build`

---

## 11. 交付完成标准

满足以下条件才算完成：

- 用户可在设置页设定默认存储方式
- 批量上传时可对每本书单独改存储方式
- 不修改的项自动继承默认值
- 后端按每项真实方式落库和写入存储
- 详情页 / 文件列表页可看出实际存储状态
- 云未配置时的边界行为清楚
- 类型检查、Lint、必要时构建通过
