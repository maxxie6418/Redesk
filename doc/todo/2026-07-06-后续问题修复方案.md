## 1. 批量抓取信息、批量设置、批量更新封面

- 页面拆分原则：
  - `书库文件` 保持为独立业务页，不并入“设置”。
  - `设置 -> 批量管理` 作为管理员专用的系统级批处理入口。
  - 拆分依据不是“数据对象是什么”，而是“用户以什么使用立场进入页面”。
- 使用立场划分：
  - `书库文件`：面向日常整理文件的人，处理单文件查看、关联、修正、删除、状态检查。
  - `批量管理`：面向维护系统和大批量修复的人，处理批量导入、批量抓取、批量更新、批量补发云端。
- 结论：
  - 不建议把“书库文件”整体合并进“设置”。
  - 建议把当前散落在业务页里的重批量入口逐步抽离到“批量管理”，但保留 `书库文件` 里的轻量操作和单文件主流程。
- 统一入口约束：
  - 在“设置”内新增一个管理员专用页签：`批量管理`。
  - 只有管理员可见、可进、可执行；普通用户不显示入口，后端接口也必须做管理员校验。
  - 批量上传、批量导入、批量更新、批量抓取、批量发送到 OSS / R2 这类高影响操作，统一收口到该页，不再分散在书架主视图。
- 页签建议分组：
  - `批量导入`：批量上传文件、CSV / Excel 导入书目、临时文件池处理。
  - `批量更新`：批量设置字段、批量分类/标签/可见性/收藏、批量补录录入原因。
  - `批量抓取`：批量抓取元数据、批量抓取封面、抓取结果确认与应用。
  - `批量存储`：批量补发到 OSS / R2、查看失败记录、重试云端同步。
- 页面信息架构草案：
  - 一级导航：
    - `书库文件`
    - `设置`
  - `书库文件` 页面保留：
    - 文件列表
    - 单文件关联书籍
    - 单文件删除
    - 文件格式/大小/存储状态查看
    - 未关联文件筛选
    - “进入批量管理”跳转入口
  - `设置 -> 批量管理` 页面承接：
    - 批量上传文件
    - 批量导入书目
    - 批量抓取元数据/封面
    - 批量更新字段
    - 批量发送到 OSS / R2
    - 批处理结果、失败列表、重试

- 目标：把“单本信息抓取/应用”升级为“选中多本后统一执行”，避免重复进入详情页。
- 前端入口：
  - 书架页保留轻量筛选与单本操作，不再承担重批量入口。
  - 所有批量能力从“设置 → 批量管理”进入，减少主书架页面的操作负担。
  - 详情页保留单本入口，不与批量入口混用。
- 后端拆分：
  - 新增批量元数据抓取接口，只负责拉取候选数据，不直接覆盖现有字段。
  - 新增批量应用接口，按字段白名单写入，避免把空值批量覆盖进数据库。
  - 封面批量更新优先复用现有 `/books/covers/batch-fetch`，再补“按选中结果应用封面”的统一回写。
- 数据规则：
  - 批量设置只允许明确字段，如状态、分类、常规分类、标签、可见性、收藏、录入原因。
  - 批量抓取结果必须让用户确认覆盖范围，默认不覆盖已有人工编辑过的字段。
- 建议落点：
  - 设置页：`apps/web/src/routes/settings/page.tsx`
  - 新页签：建议新增 `apps/web/src/routes/settings/batch-management-tab.tsx`
  - 前端：`apps/web/src/routes/bookshelf/*`、`apps/web/src/hooks/use-books.ts`
  - 后端：`apps/api/src/routes/books.ts`
- 验收：
  - 普通用户看不到“批量管理”页签。
  - 管理员能在一个集中页里完成导入、更新、抓取、补发 OSS / R2。
  - `书库文件` 页面仍能独立完成日常单文件管理，不依赖进入“设置”。
  - 选中多本后可一次完成抓取和应用。
  - 封面批量更新不会误改未勾选书籍。
  - 已有人工值的字段默认安全。

## 2. UI 样式不一致

- 当前问题主要集中在原生下拉、筛选器、详情页编辑器、提醒消息四类控件风格不统一。
- 修复原则：
  - 所有筛选下拉统一走同一套组件，不再混用原生 `<select>`、自定义按钮组、临时样式。
  - 所有状态提醒统一走一套消息组件，避免同时存在 `sonner`、页内浮条、局部 toast 三种视觉规范。
  - 颜色、圆角、边框、阴影、悬停态收敛到同一组变量。
- 建议落点：
  - `apps/web/src/components/ui/select.tsx`
  - `apps/web/src/components/page-ui/filter-select.tsx`
  - `apps/web/src/routes/settings/status-toast.tsx`
  - `apps/web/src/components/book-detail-sheet/editable-select-field.tsx`
- 执行顺序：
  - 先统一组件，再回收页面内散落样式，避免边改边分叉。

## 3. 登录口令被书籍卡片遮挡

- 现状判断：
  - 侧边栏登录入口使用的是局部悬浮卡片，而不是全局模态层。
  - 该方案容易被书架内容区、详情抽屉或局部滚动容器干扰。
- 修复方案：
  - 把 `LoginDialog` 从侧边栏内嵌浮层改为全局 `Dialog/Modal`。
  - 使用视口级遮罩和固定定位，保证登录层级始终高于书架卡片、详情抽屉和移动端面板。
  - 登录弹层打开时锁定背景滚动，避免误触书架内容。
- 建议落点：
  - `apps/web/src/components/app-sidebar.tsx`
  - `apps/web/src/components/login-dialog.tsx`
  - 可复用 `apps/web/src/components/ui/dialog.tsx`
- 验收：
  - 登录弹层在桌面端和移动端都不会被书籍卡片遮挡。
  - 打开详情抽屉时再点登录，也仍然位于最上层。

## 4. 阅读时工具条细节优化

- 现状判断：
  - 当前 `HighlightToolbar` 只有高亮、划线、附注三类动作，信息层级和定位策略都偏基础。
- 修复方案：
  - 将“高亮颜色”“划线颜色”“附注”分组，主动作放前，次动作收后。
  - 增加越界修正：靠近窗口顶部或左右边缘时自动翻转或偏移，避免工具条被裁切。
  - 增加键盘与交互细节：`Esc` 关闭、重复点击时保留选区反馈、移动端增大触控面积。
  - 先做交互与样式优化，不提前塞入 M2 之外的新业务能力。
- 建议落点：
  - `apps/web/src/components/highlight-toolbar/index.tsx`
  - `apps/web/src/routes/book-reader.tsx`
- 验收：
  - 各种选区位置都不会把工具条挤出视口。
  - 工具条动作分组更清楚，误触率下降。

## 5. 书籍卡片显示内容整理

- 现状判断：
  - 书架存在多种卡片视图，但信息层级还不够稳定，容易出现重复、拥挤、轻重不分。
- 修复方案：
  - 定义统一信息优先级：书名 > 作者 > 状态/评分/收藏 > 分类/标签 > 可阅读/文件状态。
  - 说明性长文本不进卡片，卡片只保留扫描型信息。
  - 把“有文件”“可阅读”“无封面”“来源链接”等派生状态做成轻量徽标，不与正文抢主视觉。
  - 四种卡片视图共享同一套字段取舍规则，只允许排版不同，不允许信息口径不同。
- 建议落点：
  - `apps/web/src/routes/bookshelf/components.tsx`
  - 可抽出共享卡片元信息片段，减少四套视图分叉。

## 6. 书籍属性格式优化，并增加“录入原因”字段

- 现状判断：
  - 当前详情页里“简介”和“阅读目的”已经存在，但缺少“为什么录入这本书”的独立字段，导致这类内容被误塞进简介。
- 修复方案：
  - 新增显式字段 `entry_reason`，只表达“录入/收藏原因”，不与 `description`、`reading_purpose` 混用。
  - `description` 保持“书籍简介/内容简介”语义。
  - `reading_purpose` 保持“阅读方式或使用方式”语义。
  - 元数据抓取与应用时，不允许外部简介自动覆盖 `entry_reason`。
  - 导入模板、导出字段、详情页编辑区同步补齐该字段。
- 建议落点：
  - 数据层：`packages/db/src/schema/books.ts`、迁移文件
  - 共享类型：`packages/shared/src/schemas.ts`
  - 后端：`apps/api/src/routes/books.ts`
  - 前端：`apps/web/src/components/book-detail-sheet/page.tsx`、`apps/web/src/components/book-edit-form.tsx`
- 验收：
  - “简介 / 阅读目的 / 录入原因”三者边界清楚。
  - 抓取元数据后不再把录入原因误写进简介。

## 7. 详情编辑状态串页，每本书应独立

- 现状判断：
  - `BookDetailSheet` 内部 `editMode` 是局部状态，但组件在切换书籍时未重置，导致从 A 书切到 B 书仍保留编辑态。
- 修复方案：
  - 先做最小修复：当 `bookId` 或 `open` 变化时，重置 `editMode`、封面面板、元数据弹层、临时提示状态。
  - 如果后续要保留“每本书各自记住是否在编辑”，再升级为 `Record<bookId, boolean>` 的按书状态映射；当前不必一步到位。
- 建议落点：
  - `apps/web/src/components/book-detail-sheet/page.tsx`
- 验收：
  - A 书进入编辑态后切到 B 书，B 默认是浏览态。
  - 关闭详情再重新打开，也不会继承上一本书的脏状态。

## 8. 文件未实际发送到 Cloudflare R2

- 现状判断：
  - 当前三态写入逻辑允许 `partial_failed`，但前端只显示同步状态，问题定位信息不足。
  - 用户感知是“选择了云端/双写，但文件并没有真正到 R2”。
- 修复方案：
  - 把“配置可用”和“对象已实际写入”分开校验。
  - 在云端写入后增加对象存在性确认；`cloud_only` 写失败时直接判整次上传失败，不允许伪成功。
  - `dual` 模式写失败时保留本地副本，但必须记录明确错误，并提供重试入口。
  - 为存储状态补充最近一次同步错误信息，便于前端展示和后续排查。
  - 增加独立的“测试云端连接/测试写入”动作，避免只看配置字段就认为可用。
- 建议落点：
  - `apps/api/src/lib/s3-storage.ts`
  - `apps/api/src/lib/storage-factory.ts`
  - `apps/api/src/routes/files.ts`
  - `apps/api/src/routes/storage.ts`
  - 前端状态展示：`apps/web/src/routes/file-library/components.tsx`、`apps/web/src/components/book-detail-sheet/page.tsx`
- 验收：
  - 选择 `cloud_only` 上传时，R2 中必须能看到对象，否则接口直接报错。
  - 选择 `dual` 时，若云端失败，前端能看到“部分失败 + 可重试”，而不是误认为成功。

## 9. 书库文件列表里“关联书籍”列应与“文件名”列放在一起

- 修复方案：
  - 调整文件表格列顺序为：文件名 → 关联书籍 → 格式 → 大小 → 存储位置 → 上传时间 → 操作。
  - 关联书籍为空时，保留未关联徽标，但位置仍紧跟文件名，便于快速扫读。
- 建议落点：
  - `apps/web/src/routes/file-library/components.tsx`
- 验收：
  - 用户查看一行时，无需横向跨越多列才能确认“这个文件属于哪本书”。

## 10. 书架增加“可阅读”筛选

- 现状判断：
  - 当前书架只有 `has_files` 语义，但“有文件”不等于“可在线阅读”。
  - 依据当前产品边界，真正可阅读应优先定义为“存在可打开的主 EPUB 文件”。
- 修复方案：
  - 在书籍列表派生字段中增加 `is_readable` 或 `has_readable_file`。
  - 书架筛选新增“全部 / 可阅读 / 不可阅读”。
  - 阅读按钮可用性与该字段保持同一判断口径，避免筛选逻辑和按钮逻辑分叉。
- 建议落点：
  - 后端：`apps/api/src/routes/books.ts`
  - 前端：`apps/web/src/hooks/use-books.ts`、`apps/web/src/routes/bookshelf/index.tsx`、`apps/web/src/routes/bookshelf/components.tsx`
- 验收：
  - “可阅读”筛选结果与卡片上的阅读按钮可用状态一致。
  - PDF、TXT 等仅存档文件不会被误算为“可阅读”。
