## 1. 总览与分批策略

### 1.1 背景

M1 主里程碑已闭环（见开发执行计划 v1.1.0），但书架管理的信息厚度与操作便利度仍有缺口。经过 v1.1.0/v1.2.0 两轮讨论，确定了一批打磨功能。本计划把这些功能拆分为技术执行项，按依赖顺序分三批推进。

### 1.2 分批原则

- **第一批**：数据层变更 + 核心 API 扩展。先补全 books/categories/bookmarks 表结构和对应的 CRUD 端点，为后续功能打基础。
- **第二批**：文件管理增强。依赖第一批的数据层（如 genre_category_id 用于筛选），独立于 AI Agent。
- **第三批**：AI Agent 接入。独立模块，不依赖前两批，但因用户说"M2 开始前做出来"，放在最后一批，细节执行前再确认。

### 1.3 批次关系图

```
第一批（数据层+核心API）
  ├── books 表新字段 + 分类拆分 + bookmarks 表
  ├── 收藏端点 + 筛选扩展 + 批量补充
  └── 前端：详情页新字段 + 首页收藏筛选
         ↓
第二批（文件管理增强）
  ├── 文件去重（checksum 校验）
  ├── 临时文件池 + 匹配界面
  ├── 书库文件视图（侧边栏入口）
  └── 创建时带文件
         ↓
第三批（AI Agent 接入）
  ├── api_tokens 表 + Bearer 鉴权
  ├── scope 校验 + 速率限制 + 审计日志
  ├── 设置页：Token 管理 + 操作日志
  └── 速率限制配置项
```

## 6. 执行顺序自检

### 6.1 依赖关系检查

- P1（数据层+核心API） → P2（文件管理增强）：P2 依赖 P1 的 schema 变更（如 genre_category_id），顺序正确
- P1 → P3（AI Agent）：P3 部分依赖 P1 的新字段（创建书籍端点需一致），但 P3 可与 P2 并行
- P2 内部：P2-01（去重）独立，P2-02~P2-03（临时池）依赖 P2-01 的 checksum 机制，P2-04（文件视图）可独立
- P3 内部：P3-01~P3-02（表） → P3-03~P3-06（中间件） → P3-07~P3-09（API） → P3-10~P3-13（前端）

### 6.2 技术一致性检查

- 所有时间戳统一 ISO 8601 UTC 字符串（与现有代码一致）
- 数据库列 snake_case，TS 变量 camelCase（与现有代码一致）
- Zod schema 放 packages/shared，前后端共用（与现有代码一致）
- 统一响应包装 + 错误处理中间件（与现有代码一致）
- token 存哈希不存明文（与密码存储策略一致：argon2 或 SHA-256，待确认）

### 6.3 未决项提醒

以下未决事项需在对应批次启动前确认：
