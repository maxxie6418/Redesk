## 项目介绍

Redesk 是一个以书籍为入口、以阅读经历为核心资产、以 AI 协同利用为长期方向的**个人知识书库系统**。

区别于单纯的书单管理工具、以阅读器体验为核心的电子书应用、或仅用于暂存文件的资源仓库，Redesk 把以下内容纳入同一套可长期积累、可持续调用的体系：

- 书籍及其元数据
- 书籍资源文件
- 阅读过程中的行为痕迹（高亮、进度）
- 阅读过程中形成的思考痕迹（笔记、判断）
- 后续可供 AI 利用的个人知识背景

### 三层架构

产品由三个层次构成，主次明确，阶段开发不得反向改变：

| 层级 | 名称 | 定位 |
| :---: | --- | --- |
| 基础层 | 书架管理 | 书籍与文件的稳定管理，长期收藏、筛选、状态流转 |
| 沉淀层 | 阅读与笔记 | 承担数据生产，把高亮、笔记、判断沉淀为可复用资产 |
| 增强层 | AI 知识书库 | 长期核心方向，基于个人阅读经历提供陪读、归纳、问答 |

### 核心价值

Redesk 的长期价值在于能否把个人阅读中真正有价值的内容长期保存并组织起来，而不在于支持的格式数量或阅读器的细节能力：

- 我拥有哪些书，我为什么保留这些书
- 我准备读什么、正在读什么、读过什么、放弃了什么
- 我在阅读中关注了哪些内容，留下了哪些判断、问题、启发
- 这些内容未来如何被自己再次使用，如何被 AI 在我的语境下调用

### 数据主权

数据存于本地 SQLite，自托管 Docker 部署，不默认强依赖云端。核心数据支持导出（Markdown / JSON / CSV）与全量备份，不绑架你的数据——即使有天 Redesk 不在了，你的笔记用任何文本编辑器都能打开。

### 工程地基

- pnpm monorepo：`apps/api`、`apps/web`、`packages/db`、`packages/shared`
- Fastify 后端：健康检查、配置加载、CORS、统一错误处理、鉴权接口、Zod 校验
- Drizzle + better-sqlite3：S1 全套表迁移 + FTS5 全文检索 + 启动时自动迁移
- Vite + React 前端：路由、Query、shadcn/ui、主题壳、侧边栏、暗色模式
- 本地启动脚本：`start-local.bat` / `start-local.ps1`
- Dockerfile 与 docker-compose 部署文件

### 已上线功能（M1 闭环）

**书库管理：**
- 书籍全生命周期：录入、编辑、详情、列表、搜索、筛选、排序、分页、批量操作
- 五状态体系：收录 / 计划读 / 在读 / 已读 / 存档，状态变更历史可追溯
- 回收站：软删除、恢复、彻底删除、清空、保留期配置
- 丰富元数据：书名/作者/副标题/译者/原作名/页数/ISBN/出版社/来源链接/阅读目的/自定义属性
- 收藏功能（favorited_at）：与状态正交，独立二态标记
- 阅读时间：started_at / finished_at，状态变更自动填充，支持手动修改
- 分类双类型：常规分类（客观类型）+ 个人分类（对个人的用途），一书一分类
- 标签：多对多，自由标记
- 书籍关联关系管理 + 规则版重复检测（作者+标题相似度）

**文件管理：**
- 一书多文件，主阅读文件标记
- 文件上传/下载（支持 Range）/替换/删除
- EPUB 封面自动抽取 + 多封面管理（EPUB 抽取/用户上传/切换激活）
- **三态存储策略**：仅本地 / 仅云端 / 本地+云端双端保留
- 文件真实存储位置与同步状态展示
- checksum（SHA-256）去重校验
- 书库文件视图：全局文件列表 + 未关联文件池 + 匹配书籍
- 云存储配置（S3 兼容，如 Cloudflare R2）

**导出与备份：**
- 元数据导出：JSON / CSV（单本 / 多本 / 全书架）
- 文件批量下载
- 手动全量 ZIP 备份（数据库 + 文件 + Markdown）
- SQLite 自动备份（定时 VACUUM，最多保留 7 份）

**集成与设置：**
- OPDS 1.2 输出（KOReader 兼容）：catalog / by-status / by-tag / search / download
- 设置页：通用设置、AI 配置、访问控制、分类管理、标签管理、备份恢复、快速链接
- 概览首页：总数/各状态数量/最近新增/最近阅读
- 侧边栏快速链接：自定义，支持增删改排序
- 空状态友好引导

说明：当前本地开发模式临时免登录（`VITE_AUTH_DISABLED=true`），便于推进功能开发；后端鉴权链路仍保留，生产构建默认不免登录。

## 🛠️ 技术栈

技术路线：**全栈 TypeScript（Route A）**。选型主因为"选错最好补救"——AI 形态未定型时，可加 Python RAG 边车而不推倒主应用。

| 类别 | 技术选型 |
| --- | --- |
| 后端 | Node.js + Fastify + better-sqlite3 + Drizzle ORM |
| 前端 | Vite + React + TypeScript + shadcn/ui |
| 存储 | SQLite 单文件（FTS5 全文检索 + sqlite-vec 向量检索） |
| 阅读器 | epub.js（CFI 锚定进度与高亮） |
| 笔记 | TipTap 富文本（HTML + Markdown 双存） |
| 部署 | 自托管 Docker（docker-compose） |
| AI | 外部 LLM API，`AIService` 接口隔离，分阶段引入 |

## 🎯 核心设计原则

- **`存档` 是独立状态，不是删除**：五状态之一，与回收站软删除是两条路径。
- **主题只引用不占有**：高亮/笔记归原书所有，主题是重组再利用层。
- **AI 内容与用户内容隔离**：AI 生成内容作为派生资产单独存放，不混入原始笔记。
- **数据主权**：导出用通用格式（Markdown/JSON），不依赖专有结构。
- **预留多用户**：用户拥有的根实体带 `owner_id`，从属关系表通过父表继承归属，当前单账户无感，未来可演进。

## 🚀 部署与开发

### 环境要求

- **Node.js**：>= 20
- **pnpm**：最新版（通过 `npm install -g pnpm` 安装）

### 本地启动

首次运行前，需在项目根目录安装依赖：

```bash
pnpm install
```

Windows 下可直接双击：

```text
start-local.bat
```

脚本会打开 API 与 Web 两个服务窗口，并在服务就绪后自动打开：

```text
http://localhost:5173/
```

也可以手动启动：

```bash
pnpm dev
```

常用命令：

```bash
pnpm dev          # 同时启动 API 与 Web
pnpm dev:api      # 仅启动后端，默认 http://localhost:8787
pnpm dev:web      # 仅启动前端，默认 http://localhost:5173
pnpm db:migrate   # 执行数据库迁移
pnpm typecheck    # 类型检查
pnpm lint         # ESLint 检查
pnpm build        # 生产构建
```

### 临时免登录

本地开发默认免登录：

```env
VITE_AUTH_DISABLED=true
```

如需恢复登录/初始化页，在 `.env` 中设置：

```env
VITE_AUTH_DISABLED=false
```

后端鉴权接口仍保留；生产构建默认不免登录。

### Docker

Docker Compose 运行前必须提供强随机 `SESSION_SECRET`，例如在 `.env` 中设置：

```env
SESSION_SECRET=your-long-random-secret
```

然后运行：

```bash
docker compose up -d
```
