# 主题阅读完善计划

日期：2026-07-06

## 1. 结论

当前“主题阅读”不是纯高保真静态占位，但也远未闭环。

- 已有基础：
  - 数据层已落表：`topics`、`topic_books`、`topic_highlights`、`topic_notes`、`topic_segments`、`topic_entries`
  - 后端已提供一部分真实接口：话题 CRUD、话题详情聚合、话题关联书籍、话题沉淀内容
  - 前端已接入真实 `topics` 数据，能创建话题、打开工作区、显示已关联书籍/高亮/笔记/沉淀内容
- 关键缺口：
  - 话题还不能真正“吸纳”阅读痕迹：缺少高亮/笔记/章节片段加入话题的完整链路
  - 工作区内多个按钮仍是样子货，未接实际动作
  - 阅读器、阅读笔记页、书籍详情页没有把“加入话题”串起来
  - AI 区仍是占位，不应与本轮闭环混做

结论建议：

- 先把“无 AI 的主题阅读闭环”提前做完，作为阅读沉淀层的收口。
- AI 话题总结、话题问答、观点冲突发现继续留在 M4，不混入本轮。

## 2. 当前现状盘点

### 2.1 已完成的真实部分

1. 话题基础数据模型已存在，且符合“引用而非拥有”的方向。
2. `apps/api/src/routes/topics.ts` 已支持：
   - 话题列表
   - 新建/编辑/软删除话题
   - 话题详情聚合
   - 关联书籍增删
   - 沉淀内容新增/编辑/删除
3. `apps/web/src/routes/reading-topics/index.tsx` 已接真实接口：
   - 话题列表来自后端
   - 新建话题可落库
   - 打开工作区可看到真实书籍/高亮/笔记/沉淀
4. 阅读器与阅读笔记主链路已基本具备：
   - 阅读进度保存/恢复
   - 高亮、划线、附注
   - 独立笔记
   - 笔记页跳回原文

### 2.2 仍是占位或半成品的部分

1. 话题工作区里的“添加书籍”“编辑话题”“新建沉淀”“引用到沉淀”“回到书中”按钮，大多没有实际行为。
2. 话题页的搜索、排序、筛选控件没有接真实状态与查询。
3. 话题详情虽然能展示高亮/笔记，但当前没有“把高亮/笔记加入话题”的入口和接口。
4. `topic_segments` 只有表结构，没有实际业务链路。
5. AI 辅助区仍是视觉占位。

## 3. 主要缺口

### 3.1 后端缺口

1. 缺少话题关联高亮接口：
   - `POST /topics/:id/highlights`
   - `DELETE /topics/:id/highlights/:highlightId`
2. 缺少话题关联笔记接口：
   - `POST /topics/:id/notes`
   - `DELETE /topics/:id/notes/:noteId`
3. 缺少话题片段接口：
   - `POST /topics/:id/segments`
   - `PATCH /topics/:topicId/segments/:segmentId`
   - `DELETE /topics/:topicId/segments/:segmentId`
4. 缺少更完整的列表能力：
   - 搜索
   - 排序
   - 分页
   - 书籍数/痕迹数等统计字段统一输出
5. 话题详情聚合目前是可用版，但还缺：
   - 段落/片段返回
   - 更稳定的排序约定
   - 引用数量统计

### 3.2 前端缺口

1. 话题列表页缺少真实搜索、排序、空态/错误态处理。
2. 话题工作区缺少可执行动作：
   - 添加书籍
   - 编辑话题名称/说明
   - 新建沉淀内容
   - 编辑/删除沉淀内容
   - 从痕迹卡片跳回阅读器
   - 从痕迹卡片引用到沉淀
3. 缺少“从别处加入话题”的入口：
   - 阅读器高亮后加入话题
   - 阅读笔记页将高亮/笔记加入话题
   - 书籍详情页从当前书发起主题
4. 目前话题工作区对书籍、高亮、笔记的统计基本是假值或弱值，需要改为真实统计。

### 3.3 产品边界缺口

1. 当前代码已经把主题提前做了基础骨架，但文档仍把主题阅读整体放在 M4，口径不一致。
2. 若不先收边界，容易把“主题核心闭环”和“AI 主题分析”混在一轮里，范围会失控。

## 4. 建议范围

### 4.1 本轮必须完成

目标：完成“无 AI 的主题阅读闭环”。

包括：

1. 话题 CRUD 完整可用。
2. 书籍可加入/移出话题。
3. 高亮可加入/移出话题。
4. 笔记可加入/移出话题。
5. 章节片段可手动加入话题。
6. 工作区可新增/编辑/删除沉淀内容。
7. 可从话题里的高亮/笔记/片段跳回原书原位置。
8. 阅读器与阅读笔记页提供“加入话题”入口。

### 4.2 本轮不做

1. AI 生成话题总结
2. AI 话题问答
3. AI 发现观点冲突
4. RAG 检索与向量召回
5. 复杂工作区协作能力
6. 自动从整章批量抽片段

## 5. 执行计划

### 阶段 A：补齐后端闭环

1. 为 `topic_highlights`、`topic_notes`、`topic_segments` 增补 Zod schema 与 API。
2. 所有关联写入都做 owner 校验，确保只能引用自己名下书籍/高亮/笔记。
3. 统一重复关联、已删除话题、来源不存在时的错误语义。
4. 话题详情接口补全：
   - `segments`
   - 更稳定的排序
   - 书籍数、痕迹数、沉淀数

验收标准：

- 通过 API 可完整维护一个话题的书籍/高亮/笔记/片段/沉淀内容。

### 阶段 B：补齐话题页真实操作

1. 让“添加书籍”接入书籍选择器并实际写入。
2. 让“编辑话题”可修改名称和说明。
3. 让“新建沉淀”接入真实表单并落库。
4. 让“引用到沉淀”可把当前高亮/笔记转为沉淀内容的引用素材。
5. 让“回到书中”跳到对应 `book_id + cfi`。
6. 搜索、排序、筛选至少做到本地可用，必要时再升级后端查询。

验收标准：

- 不离开话题页即可完成一个话题的整理与沉淀。

### 阶段 C：补齐跨页入口

1. 阅读器高亮/附注后可直接“加入话题”。
2. 阅读笔记页每条高亮/笔记可加入某个话题。
3. 书籍详情页可“从本书发起主题”，自动关联当前书。

验收标准：

- 用户在阅读中产生痕迹后，最多两步进入某个话题。

### 阶段 D：文档与收尾

1. 同步 `doc/技术方案.md`、`doc/开发执行计划.md` 的当前状态描述。
2. 明确口径：
   - “主题基础骨架已前置”
   - “AI 主题分析仍留在 M4”
3. 补最小测试：
   - 话题关联高亮/笔记/片段接口
   - owner 边界
   - 删除原始高亮/笔记后引用自动摘除

验收标准：

- 文档与代码口径一致，主题能力边界清楚。

## 6. 推荐优先级

### P0

1. 话题关联高亮/笔记 API
2. 话题工作区真实增删改
3. 话题内回到原文
4. 阅读器/笔记页“加入话题”入口

### P1

1. `topic_segments` 手动片段能力
2. 话题搜索/排序/筛选完善
3. 统计字段真实化
4. 详情页从当前书发起主题

### P2

1. 更复杂的话题工作区
2. AI 辅助区落地
3. 向量检索与 RAG

## 7. 建议实施顺序

建议按下面顺序推进，避免前端继续套占位：

1. 先补 `topic_highlights` / `topic_notes` / `topic_segments` 接口。
2. 再把 `reading-topics` 页面的假按钮全部接实。
3. 然后从阅读器、阅读笔记页补“加入话题”入口。
4. 最后再同步文档与补测试。

## 8. 完成标志

满足以下条件，可认为“主题阅读基础闭环”完成：

1. 新建一个话题。
2. 把一本书加入该话题。
3. 从阅读器或阅读笔记页，把高亮/笔记加入该话题。
4. 在话题内补一条“问题/判断/比较”沉淀。
5. 从话题里的任一痕迹跳回原书原文。
6. 删除原始高亮或笔记后，话题内引用自动消失，不污染原书数据。
7. 整个流程不依赖 AI。

## 9. 一句话判断

现在最合理的做法不是重做主题页，而是把现有“数据层已先行、页面壳已接半套”的实现补到闭环；核心是补“痕迹进入主题”和“主题回到原文”这两条链路。
